- **`nova-nix eval` writes a census of its C data layer to the file `NOVA_NIX_C_STATS` names: the objects and bytes of each kind it allocated, those the result, the root environment, the import cache and the search path still reach once evaluation returns, and what finding them cost.** The C data layer holds most of an evaluation's memory and frees nothing before the process exits, and nothing said where that memory went: a heap profile sees GHC's heap alone. Upstream reports its own figures under `NIX_SHOW_STATS` (eval.cc:2816-2965 at 2.24.9), counts of what it allocated; the census gives those counts for the C side and also what is still reached. It reads only what the allocators already keep, so an evaluation without the variable does no extra work, and its mark frees and writes nothing. What it reaches is exact for those roots. A C object that only a Haskell value outside them holds is counted as unreached, and once evaluation has returned such values are constants of the program, whose number does not grow with the evaluation. Symbols are reached through the values that hold them and not through the compiled code that names them, and code is counted but never marked, since nothing frees it. (#474)
- **Library API:** `Nix.Eval.CStats` takes a census and renders it: `takeCensus :: [CRoot] -> IO (Either CStatusError Census)`, with the roots a value holds from `valueRoots :: NixValue -> [CRoot]`, and `renderCensus :: Census -> ByteString`.
