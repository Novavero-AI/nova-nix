- **`store gc` and `store delete` refuse a store directory that upstream Nix's database also manages, such as `/nix/store` where upstream Nix is installed, and name that database.** The collector deletes every entry in the store directory that nova-nix's own roots do not keep, and a path upstream registered has no row in nova-nix's database, so in a store shared with a single-user upstream install, or with nova-nix run as root, `store gc` deleted every upstream path and left upstream's database naming paths that no longer existed; `store delete` removed a named upstream path the same way. The refusal looks for upstream's database where upstream's local store keeps it: `/nix/var/nix/db/db.sqlite` for `/nix/store`, and `<root>/nix/var/nix/db/db.sqlite` for a store upstream opens with a root at `<root>/nix/store` (`LocalFSStoreConfig` and `LocalStore` at 2.24.9). It looks only beside a directory named `nix/store`, the name of upstream's default store and of every store it opens with a root, both as the store is spelled and as its links resolve, so a store of nova-nix's own beside upstream's, such as `/nix/nova-store`, is collected as before. A store is refused too when that path cannot be examined, such as under a directory this user cannot search, since it may be that database. An upstream whose state directory is moved, by `NIX_STATE_DIR` or by its build, is not recognised, nor is a store reached through a bind mount. `store gc --print-roots` still lists the roots.
- **Library API:** `Nix.Store.GC.upstreamDatabasePath` gives the database upstream would keep for a store directory, when upstream keeps stores in a directory of that name, and `collectGarbage`, `withLiveSet` and `deleteStorePathRaw` return `Left` for a store with one.
