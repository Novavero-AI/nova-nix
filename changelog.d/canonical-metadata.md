- **A path added to the store takes upstream's canonical metadata: every file and directory is made `0444`, or `0555` when its owner may execute it, and every node, a symlink's own included, has the modification time 1, a second past the epoch, as upstream's `canonicalisePathMetaData` leaves them (posix-fs-canonicalise.cc at 2.24.9).** nova-nix cleared only the owner's write bit, so a path kept the times it was written with and the group and other bits of whatever wrote it: a file a NAR or `builtin:unpack` marked executable could be executed by its owner alone, and a `.drv` stayed writable. Upstream canonicalizes a build's outputs (`registerOutputs`, local-derivation-goal.cc at 2.24.9, derivation-builder-impl.cc at 2.36.0), a substituted or downloaded path (`LocalStore::addToStore`, local-store.cc) and whatever `addToStoreFromDump` adds, which is every other store write an evaluation makes and each `.drv` (local-store.cc). Here that is a build's outputs, a substituted path, each store object an evaluation writes, as it writes it (`builtins.toFile`, `builtins.fetchurl`, `builtins.fetchTarball`, `builtins.fetchGit`, `builtins.path` and `builtins.filterSource`), the sources a build restores, and each `.drv` a build writes, including a tree on disk that already reproduces its address, or that `builtins.fetchGit`'s cache names, and is kept as it is. So `eval` alone leaves a `builtins.fetchTarball` tree as `nix-instantiate` 2.24.9 does: a file `0444` and an executable `0555`, each with the time 1, where nova-nix left what its restore wrote, `0644` and `0744` under the usual umask, with the time of the restore. As upstream's does, the walk drops the setuid, setgid and sticky bits, leaves a symlink's mode alone, keeps a node's access time to the whole second, gives a node another user owns to the process's user and group, and fails a path holding a node that is not a regular file, a directory or a symlink with `file '<path>' has an unsupported type`. A NAR records only the owner's execute bit, which the canonical mode keeps, so no store path or NAR hash changes. Upstream also clears a node's file flags on macOS and its extended attributes on Linux; nova-nix does neither. On Windows, where upstream sets no times and has no modes, each file and directory is given the read-only attribute, as before, and the same time, and a symlink the time.
- **Library API:** `Nix.Store.setReadOnly` is replaced by `canonicalizeMetadata`, from the new module `Nix.Store.Metadata`; `Nix.Store` re-exports it. The module also exports the canonical form: `metadataChanges` gives the `MetadataChange`s a node's `NodeMetadata` needs, and `canonicalPermissions`, `readOnlyPermissions`, `executablePermissions` and `storeModificationTime` are its constants. `writeDrvAterm` keeps a `.drv` that already holds its bytes rather than writing it again. On Windows the `Win32` floor rises to 2.12, the first whose `setFileTime` leaves a time it is not given as it is.
