- **On Windows nova-nix refuses a store when its directory, its `.nova-nix` state directory or a directory on the way to them below the drive root belongs to an account other than the user nova-nix runs as, SYSTEM and Administrators, has no DACL, or lets any other account change it, and the error names the directory and what is wrong with it.** A drive root lets every signed-in user create a folder in it, so on a machine where install-nova-nix never ran another user could create `C:\nix` first; nova-nix then made its protected store inside a folder that user owned, and as its owner they could give themselves the right to delete what it holds, move the store aside and put a store and database of their own in its place, which the next build would run from. nova-nix now holds each of these directories that already exists to install-nova-nix's rule for `C:\nix`: its owner is the user, SYSTEM or Administrators, it has a DACL, and no allow entry of any kind, an inherit-only one included, grants another account a right that changes it. Read and execute for Users is no change. A directory is checked before nova-nix creates anything in it or reads anything from it, a read-only command's queries of the database included, since a database another account controls is as dangerous to read as to write; the error says to move the directory aside and let nova-nix or install-nova-nix create it. A `C:\nix` either of them creates passes for the user it was created for, and so does a store under the user's profile; another user's nova-nix refuses it, since it lets its creator change it. A store in a folder that took a drive root's permissions is refused, a `C:\nix` an earlier nova-nix release created among them. The drive root itself is not checked, since its default permissions let other users create a folder in it but not delete or rename one already there. A link is checked as itself, not as what it leads to, so a link the user made stands, where install-nova-nix refuses one at `C:\nix`. A store upstream Nix's database also manages, whose tree answers a read-only command's queries, is checked before the tree is read. Upstream Nix has no such check: on Linux and macOS only root can create a directory in `/`. macOS and Linux are unchanged.
- **Library API:** on Windows `Nix.Store.Access.createStateDirectory`, and through it `Nix.Store.DB.createStoreDirectories`, `openStoreDB` and `Nix.Store.openStore`, refuse such a store with a `userError`, and `Nix.Store.DB.openStoreDBReadOnly` does through the new `checkStateDirectory`. `Nix.Store.Access` gives the rule as pure functions that work on every platform: `storeDirectories` lists the directories checked, `parseSecurityDescriptor` reads a self-relative security descriptor into a `DirSecurity` of `AclEntry` values, `securityDistrust` and `descriptorDistrust` give the `Distrust` that refuses one, and `distrustMessage` words the refusal. `Sid` equality compares the accounts two SIDs name, so the hexadecimal digits of a wide authority may differ in case.
