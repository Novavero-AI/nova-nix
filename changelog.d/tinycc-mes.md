- **`pkgs/windows` builds TinyCC's own source on the Mes rung: `tinycc-mes.prev`, TinyCC at cb41cbfe compiled by `tinycc.bootstrappable`, and `tinycc-mes`, the same source compiled by that, each with the Mes C library and TinyCC's runtime its tcc compiles.** They are nixpkgs' `minimal-bootstrap/tinycc` `tinycc-mes-boot` and `tinycc-mes` derivations, each an `i686-windows` `kaem.runCommand` script, with two of nixpkgs' three edits to the source and its `tccdefs`, tcc's predefined macros compiled into it from `include/tccdefs.h` by `conftest.c`. The archive is TinyCC's GitHub mirror's of that commit, the tree nixpkgs takes from repo.or.cz, whose snapshot does not reach every client as the same gzip stream. Three things differ from nixpkgs besides the changes for PE the rounds before share. nixpkgs' third edit sets `static_link` in every compile, so that an ELF link writes a static executable; a PE tcc reads the flag only where it resolves `-l`, which it then keeps from finding a `.def` import library, so the edit is left out. `tcc.h` keys `PATHSEP`, which splits `C_INCLUDE_PATH`, `-I` and `-L`, on `_WIN32`, the host's macro, where janneke's keys it on `TCC_TARGET_PE`; every round compiles `tcc.c` with `_WIN32` undefined, so a third edit makes it `;`, since an unedited tcc would split a store path at its drive's colon. And `c2str`, which writes `tccdefs_.h`, is linked as every program of a PE round is, with `-nostdlib`, `crt1.o`, libc and libtcc1, where nixpkgs' bare link would pull in msvcrt and kernel32. Each round now carries the `C_INCLUDE_PATH` a script that runs its tcc sets, and a script sets that of the tcc it runs: `tinycc-mes.prev`'s tcc is compiled with janneke's headers and its library with TinyCC's. CI builds both rounds from the seed on x64 and ARM64, runs the last with `-version`, and runs a hello, the double's two words, and a double printed through `printf`'s `%f`, whose cast to `long` this round's libtcc1 has where Mes's stubs it, each compiled and linked by the last, checking what each prints and the status it exits with.
