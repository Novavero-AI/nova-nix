- **`pkgs/windows` builds GNU make 4.4.1 with `tinycc-native`, from make's Windows sources as its `build_w32.bat` compiles them with tcc, in one `i686-windows` `kaem.runCommand` script with no configure and no shell.** It follows nixpkgs' `minimal-bootstrap/gnumake`, which also builds make with tinycc and without configure. make's Windows configuration reads `__MINGW32__` as MinGW's headers being present and turns on headers TinyCC's do not have, so make compiles against TinyCC's own headers, as `build_w32.bat`'s tcc mode does, with `tinycc-native`'s predefined `__MINGW32__` undefined. As in nixpkgs, the directories make searches for an included makefile and for `-l` drop `/usr/gnu/include`, `/usr/local/include`, `/usr/include`, `/lib` and `/usr/lib`, which on Windows resolve against the current drive's root. The link takes `-luser32` and a one-name advapi32 import library, since TinyCC ships no advapi32 `.def`. A make compiled by tcc runs each recipe that needs a shell from a batch file, through `cmd.exe` unless an `sh.exe` is on `PATH`. CI builds it on x64 and ARM64, checks `make --version`, and has make build a target through a pattern rule whose recipe is `cmd.exe`'s `copy`.
