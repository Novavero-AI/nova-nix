- **`pkgs/windows` builds `binutils-x86_64`, GNU binutils 2.46 for `x86_64-w64-mingw32`, compiled by `gcc-latest` in the seed stdenv: the first rung of the ladder's x86_64 toolchain, which the stage-1 stdenv's 64-bit packages need.** The ladder reaches x86_64 the way MinGW-w64's own build guide and nixpkgs' `pkgsCross.mingwW64` do, through a cross toolchain: these tools, then a GCC core that compiles the runtime, the runtime, and GCC with its libraries, each running on i686 Windows. binutils is a rung of its own rather than the i686 rung rebuilt with `--enable-targets`: GCC for `x86_64-w64-mingw32` and MinGW-w64's runtime look their tools up under the target's name, which only a binutils configured for that target installs, and the i686 rung is compiled by tcc with patches and flags for tcc and msvcrt.dll. The x86_64 target's own formats include i386 PE, so these tools read and write both. The release is nixpkgs' 2.46, from the archive nixpkgs fetches; GCC 16.2.0 does not need it, since its configure tests the assembler for each feature it would use and does without what 2.41 lacks, such as `.base64`. nixpkgs' flags carry over where they mean the same here; those for ELF, Linux or MIPS are left out, the zlib of binutils' tree is linked in place of a system one, the libraries are static, so the programs import no DLL of binutils', and NLS is off, since the ladder has no gettext. None of nixpkgs' patches applies: `deterministic.patch` sets a flag the PE writer does not read, and the others serve ELF, nixpkgs' split outputs, configure scripts it regenerates on Darwin alone, AVR, or a `windres` run by a path. Every link is told to write no time stamp, which `ld` otherwise writes into a PE image. CI builds the rung on x64 and ARM64 Windows in a new stage, x86_64, which starts from the store GCC 16 now hands on. One check has `as` assemble a function, `ar` archive it and `ld` link it into an x86_64 program and an i386 one that run and exit with its value, and compares what `nm`, `ar` and `objdump` read back, and the machine and optional header magic read from each program's PE header, PE32+ for x86_64, with what the formats define; the other reads the time stamp in the header of every program the rung installs and compares the list with one in which each is zero.
