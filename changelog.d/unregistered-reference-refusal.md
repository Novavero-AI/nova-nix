- **A registration that references a path the store has not registered is refused in upstream's words, `path '/nix/store/...' is not valid`, naming the path under `/nix/store` wherever the store is kept.** The refusal read `registerPaths: <referrer> references unregistered path <reference>`, with both paths spelled under the store's own directory, so on Windows or under `--store` it named `C:\nix\store\...` or the relocated directory. Upstream refuses the reference in `registerValidPaths` through `queryValidPathId` (local-store.cc at 2.24.9, and the same at 2.34.9 and 2.35.4), which names it with `printStorePath`, and that spells a path under the logical store directory, which stays `/nix/store` for a store whose files live elsewhere (`realStoreDir`, local-fs-store.hh). Of several unregistered references the one named is the one upstream names, as the batch and each path's references are walked in path order. A build meets the refusal when a derivation or a `builtins.toFile` text carries string context naming a store path this store has not registered, as `builtins.appendContext` and `builtins.storePath` can give it, and when a cache declares references that loop between paths. Upstream's evaluation refuses such a context earlier, when `ensurePath` cannot substitute the path, and its own commands that reach this refusal are `nix-store --register-validity` and `nix-store --import`.
