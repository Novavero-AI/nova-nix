- **`pkgs/windows`'s stage0-pe32 installs kaem, mescc-tools and mescc-tools-extra as bin directories, and gives kaem nixpkgs' `runCommand`, with `writeText` beside it.** nixpkgs' Mes stage and every stage after it are `kaem.runCommand` scripts that call their tools by name (`minimal-bootstrap/stage0-posix/kaem/default.nix`), and each stage0-pe32 program was a single `.exe` file with no `bin/`. `stage0-pe32.kaem`, `mescc-tools` and `mescc-tools-extra` now hold kaem, M2-Planet (the `M2` link), M1, hex2 (from `hex2-new`) and mescc-tools-extra's thirteen programs at `bin/<name>.exe`, and keep each program as an attribute, so `stage0-pe32.mescc-tools-extra.<name>` still names it; the single-file kaem is `stage0-pe32.kaem-unwrapped`, as nixpkgs names it. kaem lays each directory out itself with mescc-tools-extra's mkdir and cp, as nixpkgs installs its kaem, so nothing runs but the chain's own programs. `kaem.runCommand name env buildCommand` runs the script with `kaem --verbose --strict`, so the first command that fails fails the build, on a PATH of the three bin directories joined with `;`, which kaem splits PATH on under Windows, trying each bare name and then with `.exe`. `writeText name text` passes the text through `passAsFile`, as nixpkgs' does, since kaem refuses an environment entry of 4,096 bytes or more. Two things differ from nixpkgs. A store path in a script is spelled from `${NIX_STORE}`, because the builder spells the store `C:\nix\store` and kaem reads a backslash in a script as an escape, so `C:\nix` would reach a command as `C:` and a newline, where kaem substitutes a variable as it stands. And `env` reaches the derivation as it stands, without nixpkgs' handling of `nativeBuildInputs`, `meta` and `passthru`, which nothing here passes. mescc-tools-extra's Windows limits apply to these scripts: cp is given the file it writes, not a directory, since it takes a destination that does not begin with `/` as relative; `mkdir -p` makes only the parents a path names before a `/`, and exits 0 even when it fails, as rm does. CI builds the bin directories on x64 and ARM64 Windows, checks each file against the program it was copied from, runs a script that calls mkdir, cp and catm by bare name, and checks that a script whose command fails fails its build.
