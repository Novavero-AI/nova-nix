- **A build asks each cache for a path's narinfo once, and takes the path's NAR from the cache whose narinfo gave the references it realised first, as upstream does.** A substitution read each path's narinfo to learn its references, then read it again before fetching the NAR, so a closure of N paths cost 2N narinfo requests, and a path no cache holds was asked about again each time a derivation that references it was tried, after its inputs as well as before. The second read could also reach another cache: when the first stopped serving the narinfo or no longer held the NAR, the NAR came from the next cache with that cache's references, which nothing had realised, the store refused the registration, and the build stopped or fell back to building. Upstream's substitution goal queries one substituter's path info, realises the references it declares, and copies the path from that same substituter, and the store's path-info cache answers every later query for the path, one for a path the substituter lacks included (`PathSubstitutionGoal::init` and `tryToRun` in substitution-goal.cc, `Store::queryPathInfo` in store-api.cc at 2.24.9). nova-nix now fetches a path with the narinfo its references came from and remembers what each cache said about each path for the rest of the build, so each narinfo is requested once; a query that failed is not remembered, as upstream caches no failure. A path whose NAR a cache fails to deliver, or no longer holds, goes to the caches after it, as upstream's goal goes to its next substituter: the next cache that serves the path has the references it declares realised first, and the path comes from it. Each output a build wants of a derivation runs its own course, as each of upstream's goals does: once one has no cache left, the others are still fetched from the caches that offer them, registering nothing, and the substitution has failed only when an output ran out of caches after one failed to deliver it, which is when upstream stops the derivation (`DerivationGoal::outputsSubstitutionTried`, derivation-goal.cc:281); otherwise the derivation builds. When the outputs wanted of one derivation arrive together and one of them comes from a later cache, the others are fetched again, since none was registered, where upstream registers each output as it arrives. Upstream's cache also expires an entry, after an hour for a path a substituter lacks and a month for one it holds (`narinfo-cache-negative-ttl`, `narinfo-cache-positive-ttl`), and keeps it on disk across runs; nova-nix remembers for one build, or one substitution of a `nova-nix trust` input, and writes nothing to disk.
- **Library API:** `Nix.Realise.SubstEffects` and `RealiseEffects` take the type of a substitute, which `Offered` carries beside the references; `SubstEffects` gains `seNextOffer`, and `seFetch` takes a `Registration`, `RegisterAll` or `RegisterNone`, and each path with its substitute, as a `NonEmpty`. `FetchOutcome` is `Fetched` or `NotFetched`, which names each path that did not arrive with an `Undelivered`, `Gone` or `DeliveryFailed`, in place of `FetchMissed` and `FetchFailed`. `Nix.Substituter.queryReferencesWith` runs in `StateT NarInfoMemo IO` and answers an `Offer Substitute`, which names the path it was checked for (`substitutePath`) and the cache it comes from (`substituteCache`); `queryNextOfferWith` asks the caches after a substitute's, `fetchSubstituteWith` fetches a substitute's path, and a run starts from `emptyNarInfoMemo`. `trySubstitute`, `trySubstituteWith` and `tryCachesWith` are removed: a path is fetched from the substitute a reference query offered, `queryReferencesWith` and then `fetchSubstituteWith`, whose `SubstResult` is about that one cache. `Nix.Builder.substitutePaths` takes a `Registration` and the substitutes.
