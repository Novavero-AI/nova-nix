- **`builtins.fetchTarball` unpacks in process as upstream 2.36.0 does, so a tarball's tree, and with it its store path, is the archive's own, and neither it nor `builtins.fetchurl` runs `curl`, `sh` or `tar`.** A tarball is downloaded through nova-nix's own HTTP client, with upstream's retries, or read from the file a `file://` URL names. It is decompressed by what its first bytes announce (gzip, bzip2, xz, zstd or none) and read as libarchive reads tar: ustar with its prefix, GNU long names and pax headers. Its entries are placed by the rules of upstream's tar sink: the last entry at a path wins, a non-empty directory cannot be replaced, and a hard link names what its target is at that point in the archive, with upstream's warning when the target is replaced. The lone top-level directory is the tree only when the archive holds nothing else at its top, so a tarball with two top-level directories keeps both, and a macOS archive's AppleDouble `._` entries are files, as upstream reads them; nova-nix stripped the first path component of every archive and let macOS's `tar` apply AppleDouble entries as metadata. The tree's NAR is streamed into the store's restore, never extracted to a directory first, so a pair of names a case-insensitive volume folds keeps both. A pin the tree does not match is refused in 2.36.0's `NAR hash mismatch in input` words, a `file://` tarball that is missing or a directory in its words, and a failure of the fetch carries upstream's `while fetching the input` line. A zip archive and a sparse archive member are refused as not yet supported, and an archive in another compression is refused as libarchive refuses an archive it does not recognize. Upstream 2.36.0 copies a fetched tree into the store only when a context needs it; nova-nix writes it at once.
- **Library API:** `MonadEval` has the methods `fetchUrlBytes` and `fetchArchiveToStore`, so an instance defines them. `Nix.Http` exports `downloadUrlWith`, the request `builtin:fetchurl` and the fetchers share. The new modules `Nix.Fetch.Tar`, `Nix.Fetch.Tree`, `Nix.Fetch.Archive`, `Nix.Fetch.Download` and `Nix.Compression.Stream` hold the tar reader, fetched trees and their NARs, the tar sink, the downloads, and the decoders.
