- **nova-nix builds against nova-cache 0.13, and a tree on disk that cannot be read is still reported as `error: ` and the failure.** nova-cache 0.13 raises a walk's failure to read an entry as `NarWalkError`, which names the access and the entry, where 0.12 raised the bare `IOException`, so the command line's report of an I/O failure no command handled, and the checks that read an unreadable tree as a mismatch or as nothing there, would have let it through to GHC's uncaught-exception report. The command line reports it as it reports an I/O failure, naming the access that failed (`/d/tree/sub: listing directory: permission denied (Permission denied)`), a failed push names it the same way, and both checks catch it. The floor on nova-cache rises to 0.13, for `NarWalkError`.
