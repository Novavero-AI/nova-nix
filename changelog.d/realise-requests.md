- **Library API:** `Nix.Realise` exports `realiseRequests`, which realises several derivations in one call, each for the outputs a request asks of it, with one record of what is realised, as upstream's `Store::buildPaths` runs a goal for each request with one worker (entry-points.cc at 2.24.9, `Worker::buildPaths` there at 2.36.0). Requests that name one derivation are realised as one request for every output any of them asks, as they share one goal upstream. Every request is assessed before any is realised, so one whose outputs are valid is realised first, and one whose derivation's attributes cannot be read or that asks for an output its derivation does not have stops the call before anything is substituted or built, as in upstream's first pass over its goals. The requests are realised and never checked, as import from derivation builds under upstream's `bmNormal` (`EvalState::realiseContext` in primops.cc); a check is of one derivation, through `realise`. The first failure stops the call, as upstream's does without `keep-going`. It answers a `RequestsFailure`: `FailedWith` a failure reported as it is, or `FailedLeaving` a request's failure with the requests it left unrealised, which `requestsFailureMessage` reports as upstream's `build of '<drv>', '<drv>' failed`; `requestsFailureStatus` gives the status the call exits with, the one failure's.
