- **`==`, `!=` and list `<` force a value both sides share before taking it as equal to itself, so `let x = throw "x"; in [ x ] == [ x ]` fails with `x`, as it does under upstream.** Two references to one thunk were taken as equal without forcing it, so an error inside a shared value never surfaced: a list or set compared with another holding the same values was `true` however those values failed, and so was `d == d.out` for a derivation whose arguments throw, since the two sets hold one `outPath`. Upstream's `eqValues` forces both values first and only then takes a value as equal to itself (eval.cc); it compares two derivations by their `outPath` through the same function (eval.cc), which forces the derivation, and list `<` calls it on each pair of elements (`CompareValues` in primops.cc). A list literal holds a variable's own value under both, so `[ x ]` and `[ x ]` share `x`. A function or NaN that both sides share is still equal to itself, as upstream's is.
