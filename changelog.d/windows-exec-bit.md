- **On Windows a file that a program built on `pkgs/windows`' stage0 tools marks executable with `chmod` is executable in its NAR, as on Linux, and the bin directories of those tools mark their programs.** nova-nix keeps a regular file's executable bit on Windows as an NTFS alternate data stream, `<file>:nova.exec`, and only `builtin:unpack`, NAR restores, store copies and `builtins.fetchGit` ever wrote one, so nothing a builder made was executable: a program built on Windows had a NAR hash different from the same output's built elsewhere, and a substituted copy was not executable. `pkgs/windows`' stage0-pe32 builds on its M2libc fork at 13e57eb, whose Windows `chmod` creates the stream when the owner execute bit is set and removes it when that bit is clear, the bit upstream's NAR serialisation reads (`S_IXUSR`), so a builder marks a program as it would on POSIX, and hex2-new's own `chmod(output, 0750)` marks what it links. The same M2libc's Windows `malloc` hands out 8-byte aligned memory, as Windows' own does on x86: it started at whatever byte the program's data ended on and did not round a block's size, and Windows fails a file call whose name's buffer is at an odd address, so `chmod` failed silently in any program whose data ended at an odd byte, mescc-tools-extra's `chmod` among them. `stage0-pe32.kaem`, `mescc-tools` and `mescc-tools-extra` follow each `cp` with `chmod 555`, as nixpkgs' do. The single-file links stay unmarked, since nothing that writes them calls chmod: hex0, hex1 and hex2 are written by the seed, hex0 and hex1, hex0 having to stay byte-identical to the seed, and the rest are linked by the hand-written hex2. A file a builder marks with MSYS2's `chmod`, or creates with M2libc's `open` and an execute mode, is still not marked (#26, #383). CI checks on x64 and ARM64 Windows that every program in the bin directories carries the stream, and builds a fixed-output script whose declared hash is its tree's NAR hash on POSIX, with the file `chmod 555` marked executable and the one `chmod 755` and then `chmod 644` left plain.
