- **`nova-nix profile history`, `profile rollback` and `profile wipe-history` show a profile's generations, switch it back to an earlier one, and delete the ones it no longer needs, so that the next `store gc` takes what only they kept.** They are `nix profile`'s commands of those names at 2.36.0. `history` prints upstream's lines for each generation in order of number: `Version N (DATE) <- M:`, where the date is the day in UTC its link was made and `M` the generation listed before it, then each package added, removed or at other versions than in that generation, with the empty-set sign for none and an epsilon for an empty version, or `No changes.`; it sets the current generation's number in green and the others' in bold where upstream 2.36.0 styles stdout, on a terminal whose `TERM` is not `dumb` or wherever `CLICOLOR_FORCE` or `FORCE_COLOR` is set, and never under `NO_COLOR` or `NOCOLOR`. `rollback` switches to the newest generation below the current one, or with `--to N` to generation `N`, every `--to` read as upstream reads it, a binary unit after it included, the last winning, and says `switching profile from version M to N`; a change after a rollback makes the generation after the newest, as upstream numbers one. `wipe-history` deletes every generation but the current one, or with `--older-than Nd` those made before its cutoff but the newest of them, which the profile held at the cutoff, and warns of one made after the cutoff that a later one predates, as upstream does; it says `removing profile version N` for each. `--dry-run` on either says what it would do and changes nothing. A generation's time is its link's own modification time, and the next collection removes a deleted generation's root record with upstream's `removing stale link` line. The refusals are upstream's, each one `error:` line: `profile version N does not exist`, `no profile version older than the current (N) exists`, the two `invalid number of days specifier` messages, and those for a `--to` that does not read, which upstream follows with a `Try 'nix --help'` line that nova-nix does not print. Where nova-nix differs: both commands keep the profile's lock file once they release the lock, as every nova-nix lock does, where upstream deletes it; both refuse a profile whose current generation is outside the store in use, as every profile command does, so a profile upstream Nix keeps in another store is neither switched nor wiped; `history` refuses a generation only `nix-env`'s `manifest.nix` describes, as `profile list` refuses such a profile, where upstream reads it; `--older-than` takes its days in 64 bits, where upstream's product is an int that more than 24855 days overflow; and of two links for one number, such as `profile-3-link` and `profile-3-link.tmp`, a rollback takes the later in name order, where upstream takes the later in directory order.
- **Library API:** `Nix.Profile.Generation` reads a profile's generations with their times and its current one (`findGenerations`), plans a rollback and a wipe as values (`rollbackPlan`, `wipePlan`), carries them out (`switchGeneration`, `wipeHistory`), and reads `--to` and `--older-than` as upstream does (`readGenerationNumber`, `parseOlderThan`); `ProfileFailure` gains `NoSuchGeneration` and `NoOlderGeneration`. `Nix.Profile.Manifest.manifestChanges` gives what changed from one manifest to the next, as a profile's history prints it, and `Nix.Store.Metadata.nodeModificationTime` reads a node's own modification time, a symlink's rather than its target's.
