- **A derivation whose builder is `builtin:buildenv`, the derivation `nix-env` evaluates for a user environment, builds as upstream's does: its output links every package its `derivations` attribute names into one tree, with `manifest.nix` linked to its `manifest`.** Such a derivation reached the path that spawns a builder, which refused it, since its `system` is `builtin`, with `no way to run a builtin builder on this machine`. The tree is upstream's `buildProfile` (builtins/buildenv.cc at 2.35.4), rule for rule. Packages are taken in order of priority, where the lower number wins, then of path, each path once, and each package's `nix-support/propagated-user-env-packages` queues the packages it names, which follow every package given at priority 1000 and up, one number per queued path in path order. An entry is linked where nothing stands. A directory where a link to a directory stands turns the link into a directory of the tree's own, holding what the link led to, resolved through every link, at the link's priority, and then the new entries at theirs; where the link leads to anything else, the build fails with upstream's `collision between ... and non-directory ...`. A file where a link stands replaces it when its priority number is lower, is passed over when it is higher, and when the two are equal fails the build with upstream's `Unable to build profile. There is a conflict for the following files:`, naming both; a file where a directory of the tree's own stands fails with `collision between non-directory ... and directory ...`. Names starting with `.` are skipped, as are `propagated-build-inputs`, `nix-support`, `perllocal.pod`, `log`, `manifest.nix` and `manifest.json` wherever they are and `dir` inside an `info` directory, an entry whose link leads nowhere, with upstream's `skipping dangling symlink` warning, and a package that is not a directory, with `not including ... in the user environment because it's not a directory`. The `derivations` attribute is read as upstream reads it: whitespace-separated tokens, empty ones dropped, in groups of an activity, a priority, an output count and that many paths, where only `false` makes an element inactive and an inactive element's paths are never read. A priority is read as `stoi` reads one, so a float priority, which `buildenv.nix` writes as `5.500000`, reads as 5. Each link names its package as the store spells it on disk: `/nix/store/...` under the default store on Linux and macOS, which are upstream's bytes, `C:\nix\store\...` on Windows, and the store directory `--store` names otherwise. Three things differ from upstream. A directory is read sorted where upstream reads it in `readdir` order, which does not change the tree but can change which pair a failure names when several entries conflict. Every package path, including those a `propagated-user-env-packages` file names, and the manifest must be a store path, in the canonical spelling or the store's own, where upstream's builder reads whatever path it is given; a sandboxed upstream build can read nothing outside its closure either, and nova-nix runs the builtin in its own process, outside any sandbox. And an attribute that ends inside an element, or a priority or count that `stoi` or `stoul` cannot read, fails with a message of nova-nix's own, where upstream reads past the last token or fails with no more than the function's name. On Windows each link is a symlink, which needs Developer Mode or an elevated shell, as a build's `result` link does.
- **Library API:** `Nix.Profile.Tree` builds the tree as a value over a `TreeReader`, the capability that reads the packages, so it runs over any store, an in-memory one included: `buildProfile`, `storeTreeReader` for a store on disk, and `writeTree`. `Nix.Builder.Buildenv` exports the builtin's name, `runBuiltinBuildenv`, and `parseDerivations`, which reads the `derivations` attribute.
