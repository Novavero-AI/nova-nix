- **A select, a has-attribute test and a variable look their name up by the symbol the compiled code holds for it, so evaluation allocates less, and a select interns a name it computes before it forces the value it selects from, as upstream's does: `builtins.seq ({ s = builtins.listToAttrs [ { name = "z" + "b"; value = 1; } ]; }.s.${"z" + "a"} or null) (({ }: null) (builtins.listToAttrs [ { name = "z" + "b"; value = 1; } { name = "z" + "a"; value = 2; } ]))` names `za` as the unexpected argument, as upstream does, where it named `zb`.** Upstream holds a variable's name and each static name of an attribute path as a symbol from parse to lookup (`ExprVar` and `AttrName`, nixexpr.hh:65-71 and :147-157 at 2.24.9) and finds it in a set by that symbol (`Bindings::get`, attr-set.hh:83-89). nova-nix's compiled code holds the same symbols, but each lookup turned its symbol back into text and interned the text again to get the symbol it started from: a variable once for every name table it walked and every `with` scope it tried, and a select or has-attribute test once for every name in its path. Each lookup now passes the symbol on, and a name a select or has-attribute test computes is interned once, where upstream's `getName` interns it (eval.cc:203-213): before a select forces the value it selects from (:1386-1396), and after a has-attribute test forces the value it tests (:1452-1454). nova-nix interned a select's computed name after that force, so a name the force interned, as `listToAttrs` interns the names of the set it builds, took the earlier symbol, and with it the earlier place in every set holding both. On `profiling/stress.nix` evaluation allocates 1.65 GB where it allocated 1.90 GB.
