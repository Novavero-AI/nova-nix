- **`nova-nix build` builds or substitutes what a path's context names before `import`, `builtins.readFile` and the other builtins that read a path read it, as upstream's import from derivation does, and `nova-nix eval` realises it as upstream's read-only evaluation does.** A path reader read the path as it was on disk with its string context dropped, so importing a derivation's output failed with `path '/nix/store/<hash>-<name>' does not exist` until something else had built it. Each reader now realises its argument's context first, as upstream's `realisePath` does (primops.cc): `import`, `builtins.scopedImport`, `readFile`, `pathExists`, `readDir`, `readFileType` and `hashFile`, `builtins.findFile` for each search path entry, and `builtins.path` and `builtins.filterSource` for a path in the store. Every path the context names must be valid, checked in upstream's order, and then each output it names is realised; when outputs several derivations lack are named, the derivation reported is the first by name, as upstream's worker takes its goals. `nova-nix build` and `nova-nix eval --aterm` add what evaluation has fetched, written or named before that (the sources it coerced, the trees it wrote, the derivations it recorded), so the store holds what upstream's would, and `build` realises through the same store handle its own build uses. `nova-nix eval` and `nova-nix trust` add nothing, as `nix-instantiate --eval` runs read-only (`main_nix_instantiate` in nix-instantiate.cc), and plain `nix-instantiate` does not. A path evaluation computed, a coerced source or a `builtins.toFile`, `builtins.path` or `builtins.filterSource` result or a derivation, is not valid there unless the store already holds it, so `import (derivation { ... })`, and equally `builtins.readFile (builtins.toFile "x" "y")`, fail with upstream's `path '<path>' is not valid`. What a fetcher fetched is readable there, since upstream's fetchers add their results in any mode (`fetch` in fetchTree.cc at 2.24.9). An output of a derivation the store holds is built when it may not be substituted (`allowSubstitutes = false`), and otherwise refused with upstream's `cannot substitute path '<path>' - no write access to the Nix store`, also for whatever that build would substitute; the output refused is the one upstream's worker tries first, by path name and then path, so a derivation's `out` comes before its `dev`. In a store upstream Nix's database manages that realisation opens nothing, so a substitution is refused in upstream's words and only an output that has to be built meets nova-nix's refusal of the store. The read-only queries make no store, metadata, database or lock, and open a store's database read-only, which writes nothing to it; SQLite still makes the `-wal` and `-shm` files a database in WAL mode needs beside one that lacks them. A database without the store's tables, as a first open cut short leaves, reads as holding nothing, as a store upstream's read-only evaluation has just made the tables of does (the new-store case of the `LocalStore` constructor in local-store.cc), and a fetched path is never asked about. What evaluation writes itself, a fetch or a `builtins.toFile` result, still makes the store directory. In a store upstream Nix's database manages, where nova-nix holds no rows, a path counts as valid when its tree exists. A failure carries upstream's line of context, `while realising the context of path '<path>'`, or `while adding path '<path>'` from `builtins.path` and `builtins.filterSource`, which also give it to a failure of the filter or the copy; `builtins.tryEval` does not catch it, and `builtins.pathExists` answers it with the failure rather than `false`. `builtins.hashFile` refuses an unknown algorithm, `builtins.filterSource` a filter that is not a function, and `builtins.path` an argument it does not take, a `filter` that is not a function or a `name` that is not a string without context, before the path's context is realised, as upstream's do; `builtins.path` gives the last two upstream's line of context, and names a copy whose `name` is empty by the path's base name. `builtins.findFile` names the entry and the path's base name, as 2.35.4 does, and where the releases word the refusal differently the newest's words are used. Under `--restrict-eval` and `--pure-eval` the closure of each output realised becomes readable, as 2.34.9 allows it (`EvalState::allowClosure` in eval.cc).
- **Library API:** `Nix.Eval.Types.MonadEval` has a new method with no default, `realiseContext :: StringContext -> m (Either ContextRefusal ())`; `PureEval` answers `Right ()`, and an instance with no store answers the same. Its `copyPathToStore` and `addFixedOutputFile` take a `PendingOrigin` first, `Fetched` from a fetcher and `Computed` from `builtins.path`. The new module `Nix.Eval.RealiseContext` holds `ContextRequest`, `SessionMode`, `PendingOrigin`, `Plan`, `planRealisation`, `firstInvalidPath`, `referenceClosure`, `ContextRefusal` and its messages, and `Nix.Eval.Context` gives a context's request (`contextRequest`). `Nix.Eval.IO.SessionSettings` gains `sessionStore`, a `SessionStore` that is `ReadOnlySession` over a `StoreQueries` and a build or `ReadWriteSession` over a `StoreOps`, and `newEvalStateWith` takes one after the search path. `Nix.Store.Ops` exports `StoreQueries` (`sqValidPaths`, `sqReferences`), `StoreOps` gains `soQueries`, and `localQueries` answers for the store in a directory without making or writing it. `Nix.Builder.BuildConfig` gains `bcSubstitution`, whose `RefuseSubstitution` refuses every substitution in upstream's read-only words (`Nix.Realise.noWriteAccessMessage`), and `Nix.Builder.realiseWithoutWriting` realises requests that way where nothing may be opened or written. `Nix.Store.DB` adds `openStoreDBReadOnly` and `storeTablesExist`. The read-only open needs `direct-sqlite >= 2.3.28`, the first release whose `open2` opens a database read-only, and wraps the handle in sqlite-simple's `Connection`, whose two fields arrived in sqlite-simple 0.4.19.0 (a minor release), so the library's bound on sqlite-simple rises from `>= 0.4` to `>= 0.4.19 && < 0.4.20`. `Nix.Store.Path` adds `isInStoreText`, upstream's `isInStore`.
