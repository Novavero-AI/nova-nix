- **A build realises each input for the outputs its dependent's `.drv` names, so a dependency on one output of a derivation fetches that output and its closure, and an output nothing asks for no longer makes the derivation build.** The dependency graph kept each input's `.drv` path and dropped the output names, and each derivation was checked and substituted for every output it has, so a dependency on `openssl.drv!dev` needed every output of openssl, and one of them missing from every cache rebuilt openssl and what it is built from. Upstream's goal for an input wants the outputs the dependent's `.drv` names (`DerivationGoal::gaveUpOnSubstitution`, derivation-goal.cc:340-376 at 2.24.9), is valid once those are (`checkPathValidity`, :1438-1514) and substitutes those alone (`haveDerivation`, :239-269); a build makes every output. nova-nix now does the same. A derivation asked later for an output it has not realised, as when one dependent wants its `dev` and another its `out`, is realised again for that output, from a cache or by a build, as upstream's worker drops a goal once it is done (`Goal::amDone`, goal.cc:189, and `Worker::removeGoal`, worker.cc:150-153) and starts a new one for the next request (`Worker::makeDerivationGoalCommon`, worker.cc:46-61). An input asked for an output it does not have, which `builtins.appendContext` can name, fails the build with upstream's `derivation '<drv>' does not have wanted outputs '<name>'` (derivation-goal.cc:1500-1503) before anything is fetched for it, where the build of its dependent refused it after the input was realised. The derivation a build is given is still realised for every output, where `nix-build` asks for the one output the expression selects (nix-build.cc:677-695). Under the output locks a build still adopts a derivation another process finished only when every output is valid, where upstream adopts it once the wanted ones are (derivation-goal.cc:699).
- **Library API:** `Nix.DependencyGraph.DepNode`'s `dnDeps` maps each dependency's `.drv` path to the outputs wanted of it, a `Map StorePath (Set Text)`, where it was a `[StorePath]`; `directDeps` still answers the paths. `Nix.Realise.RealiseEffects` drops `reAllValid`: whether the outputs wanted of a derivation are valid is asked of `reSubst`'s `seValid`. Its `reBuild` also takes the names of the outputs the request that led to the build asks for, a `Set Text`, which a build that makes every output may leave unread. `Nix.Realise.RealiseFailure` gains `MissingOutputs`, naming the derivation and the outputs it lacks, a `NonEmpty Text`.
