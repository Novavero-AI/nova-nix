- **A function holds the names of its formals, its argument and itself as the symbols the compiled code holds for them, and a call to a set pattern finds each formal in its argument by its symbol and looks for an unexpected argument only when the argument holds attributes no formal takes, as upstream's does, so making, storing, reading and calling a function allocates less.** Upstream holds a formal's name, a function's argument name and the name its binding gives it as symbols from parse to call (`Formal` and `ExprLambda`, nixexpr.hh:294-299 and :326-332 at 2.24.9). Its `callFunction` looks each formal up in the argument by that symbol and counts the formals the argument fills, and only when, with no ellipsis, that count differs from the argument's size does it walk the argument for the first attribute no formal names (eval.cc:1545-1586). nova-nix's compiled code and closures held the same symbols, but each function made from the compiled code and each one read from a cell turned every name into text, each one stored in a cell interned every name again, and each call to a set pattern interned each formal's name to look it up, then, with no ellipsis, turned every attribute of its argument into text and compared it with every formal's name. Results and errors are unchanged. A fold making 600,000 calls to set patterns, with and without defaults, an ellipsis and an `@` name, allocates 3.16 GB where it allocated 4.35 GB, in about 25% less mutator time, and on `profiling/stress.nix` evaluation allocates 1.14 GB where it allocated 1.18 GB.
- **Library API:** `Nix.Eval.EvalFormals.EvalFormal`'s `efName`, the argument name `EFName` holds and the `@` name `EFNamedSet` holds are each a `Symbol` where they were `Text`, so `Nix.Eval.Compile.decodeBcFormals` answers, and `Nix.Eval.Types.marshalLambda` stores, the symbols the bytecode and a closure hold, and `Nix.Eval.Compile.compileFormalsToEval` interns each name it compiles.
