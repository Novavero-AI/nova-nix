- **`builtins.parseFlakeRef` and `builtins.flakeRefToString` read and write flake references as upstream 2.36.0 does, and the `experimental-features` setting, with `extra-experimental-features` and the `--extra-experimental-features` flag, turns on what they need.** A reference is read as upstream reads one: as a flake ID such as `nixpkgs/nixos-24.05`, then as a URL (`github:`, `gitlab:`, `sourcehut:`, `git+`, `hg+`, `path:`, `flake:` and tarball or file URLs), then as an absolute path, each input checked as its scheme checks it and refused in its words. The GitHub, GitLab, sourcehut, path and registry forms need `flakes`, as upstream's do, and a reference that names one with the feature off is refused with upstream's `experimental Nix feature 'flakes' is disabled` message; Git, Mercurial, tarball and file references need none. Upstream 2.36.0's `nix` adds `getFlake`, `parseFlakeRef` and `flakeRefToString` to every evaluator whatever the features, so `builtins ? parseFlakeRef` is true with none on; `__getFlake` is bound, as upstream binds it, and a call fails as one of `fetchMercurial` does, until flake evaluation lands, and `builtins` leaves it out, so `builtins ? getFlake` stays false. The names 2.36.0 interns as it starts take the same places here: the internal `fetchFinalTree` among fetchTree.cc's primops, and the three flake primops after every registered one. An unknown feature's name is dropped from the setting with upstream's warning, which is printed as the command starts.
- **Library API:** `EvalPolicy` has a field `epExperimentalFeatures` and `NixConfig` one `ncExperimentalFeatures`, each a `Nix.ExperimentalFeature.FeatureSet`; a record built with every field lists it. `parseSriHash` and `parseNarHash` are exported by `Nix.Hash`.
