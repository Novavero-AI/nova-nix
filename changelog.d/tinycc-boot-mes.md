- **`pkgs/windows` builds TinyCC's first round on the Mes rung: `tinycc.boot-mes.compiler`, janneke's bootstrappable TinyCC compiled by MesCC into a tcc that writes PE32, and `tinycc.boot-mes.libs`, the Mes C library and TinyCC's runtime compiled by that tcc.** They are nixpkgs' `minimal-bootstrap/tinycc` `tinycc-boot-mes` derivations, each an `i686-windows` `kaem.runCommand` script, from janneke's fork at ea3900f, the commit nixpkgs pins. Four things differ from nixpkgs. tcc is built with `TCC_TARGET_PE`, so it writes PE32 from this round on: it is the one tcc in the chain MesCC links, so a tcc that wrote ELF here would leave every later round with nothing Windows runs. tcc has no include directory built in, and every derivation that runs it names the headers in `C_INCLUDE_PATH`, which tcc reads at startup, where nixpkgs writes them into tcc as a C string: the builder spells a store path `C:\nix\store/...`, and the backslash would start an escape. The library holds `crt1.o` alone of the startup files, since lib/windows has `crt1.c` alone. And nixpkgs' three edits to `x86_64-gen.c` and its PLT relocation in `tccelf.c`, which do not reach an i386 tcc, are not made. MesCC compiles tcc in an arena of 40,000,000 cells, twice `mes.env`'s: compiling tcc.c, the largest unit Mes compiles, Mes keeps up to 2,957,730 cells across a collection, more than the 2,000,000 the smaller arena has room to copy, which Mes does not check. `mes.libc` now carries nixpkgs' `CFLAGS`, `-std=c11`, and `mes.baseAddress` is exported, the ImageBase MesCC links tcc at. CI builds it from the seed on x64 and ARM64 Windows, runs the tcc with `-version`, and runs a program it compiled and linked with no import table, checking what it prints and the status it exits with; the x64 leg measures the cells Mes keeps while MesCC compiles and links tcc.
