- **`pkgs/windows` builds MinGW-w64 v14.0.0, the project's newest release and the one nixpkgs packages, with `gcc10`: `mingw-w64-headers-latest` installs its headers and `mingw-w64-crt-latest` compiles its runtime for `i686-w64-mingw32`, the runtime the compilers after `gcc10` are given.** The ladder's first runtime, v8.0.3, is the newest GCC 4.6.4 compiles, since later releases call `__atomic_load_n` (`misc/gettimeofday.c`), `__builtin_mul_overflow` (`misc/_recalloc.c`) and `__builtin_bswap16` (`misc/winbs_ushort.c`), which that compiler lacks and GCC 10 has. Both packages follow nixpkgs' `mingw_w64_headers` and `mingw_w64` and the ladder's v8.0.3 rungs: the headers install from the archive's own directory with no compiler, and the runtime configures its own directory from a build directory beside it with `--host=i686-w64-mingw32`, the stdenv's `CC`, `AR` and `C_INCLUDE_PATH` unset, the headers' output as its sysroot, `--enable-lib32 --disable-lib64` and `CFLAGS=-O2`. `--with-default-msvcrt=msvcrt` is nixpkgs' flag for this target and the runtime the ladder links; at this release it names msvcrt.dll's version 0x600 in `_mingw.h`, where v8.0.3 names 0x700, and makes `libmsvcrt.a` a copy of `libmsvcrt-os.a`, msvcrt.dll's import library with the functions it lacks compiled in. `_WIN32_WINNT` is the release's default, 0xa00, Windows 10, as in nixpkgs. Each file of this release's runtime has one install rule, so it installs with `$NIX_BUILD_CORES` jobs, where v8.0.3's installs with one. `gcc10` keeps v8.0.3's runtime in its own prefix: the new runtime's compiles read the new headers first, and the runtime links no program. CI builds both in the GCC 10 (Windows) stage on x64 and ARM64 Windows. One check pins every file the runtime installs, which is what the release's Makefile installs for this configuration, each a file Homebrew's mingw-w64 14.0.0 installs for i686 too, and the global symbols of `crt2.o`, which are those of the `crt2.o` GCC 16.2.0 compiled for that package, so that configure's test of whether `ld` defines `__ImageBase`, which changes the objects and not the build's exit status, shows if it fails on Windows. The other has `gcc10` link a program against the new runtime, given its directories with `-B` and `-isystem` as GCC's build gives a compiler its target's runtime: it prints the release and msvcrt.dll version the headers name, and calls `gettimeofday`, `_recalloc`, including a size whose product overflows, and `_byteswap_ushort`, each linked from the runtime's libraries.
