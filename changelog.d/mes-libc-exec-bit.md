- **On Windows a file that a program built on Mes libc marks executable, with `chmod` or by creating it with `open` and a mode that has the owner execute bit, is executable in its NAR, as on Linux.** nova-nix keeps a regular file's executable bit on Windows as the `<file>:nova.exec` stream, and Windows has no such bit for a C library to set, so a Mes libc that accepted a mode and ignored it would leave plain whatever a program linked with it marked executable, a compiler's output among them, and that output's NAR hash would differ from the same output's built elsewhere. `pkgs/windows`' Mes builds from the Novavero-AI/mes fork at d9ab4ea, whose Windows `chmod` creates the stream when the mode has the owner execute bit (`S_IXUSR`), the bit upstream's NAR serialisation reads, and removes it when that bit is clear, as the stage0 tools' M2libc `chmod` does. Its `open` marks a file it creates when the mode has that bit, since Linux applies the mode only to a file `open` creates. Mes libc keeps no umask on Windows, so `open` uses the mode as given; upstream runs its builders under umask 022 (`initNix`), which never clears the owner execute bit, so the bit comes out the same. CI on x64 and ARM64 Windows builds a fixed-output derivation in which a program MesCC compiles and links against `mes.libs` creates one file with `open` and mode 0755, one with 0644, and one with 0644 that it then `chmod`s to 0755, and whose declared hash is that tree's NAR hash on POSIX with the first and third executable.
