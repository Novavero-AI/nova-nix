- **`==` on two sets compares them pair by pair in the order their names were interned, each pair's names and then its values, so `{ zb = 1; za = throw "a"; } == { zb = 2; za = 1; }` is `false` and `{ zq1 = throw "x"; zq2 = 1; } == { zq1 = 1; zq3 = 1; }` fails with `x`, as under upstream.** The two sets' name lists were compared whole before any value, then the values in name order, so the first failed with `a` and the second was `false`. Upstream's `eqValues` compares two derivations by their `outPath`, takes sets of different sizes as unequal without forcing a value, and then walks both sets' `Bindings` together, comparing each pair's names and then its values and stopping at the first difference (eval.cc:2763-2782 at 2.24.9). `Bindings` are sorted by `Symbol`, whose order is the order the symbol table interned the name in (attr-set.hh, symbol-table.hh); a set here is sorted by its own symbol table the same way, and nova-nix interns names in upstream's order: its startup names first, then each name where upstream's parser interns it, and no string value at all, so two sets compare in upstream's order. The order decides only which failure wins, never whether two sets are equal. Comparing two sets reads one entry of each at a time, where it copied both sets' names and values first. (#484)
