- **`derivationStrict` forces a derivation's attributes in name order and only then looks for its builder and system, so the error it reports is the one upstream's reports.** It forced `system`, then `builder`, and refused either missing, then checked `outputs` and read `args`, all before the rest of the attributes, so `(derivation { name = "w"; builder = "b"; all = throw "all"; }).drvPath` failed with `required attribute 'system' missing` where upstream fails with `all`, a repeated output was reported ahead of a throwing attribute sorting before `outputs`, and with both `builder` and `system` throwing the error was `system`'s. Upstream reads `__structuredAttrs` and `__ignoreNulls` first, then makes one pass over the other attributes in name order that reads `args`, `builder`, `system` and `outputs` at their keys, and checks that the builder and system are present after it (`derivationStrictInternal` in primops.cc), and nova-nix now does the same, for a structured derivation too. As upstream's does, a derivation that passes its attributes through the environment takes its outputs from the words of the `outputs` entry, so `derivationStrict` given `outputs = "out dev"` has the outputs `out` and `dev`. An output name that is not a valid store path name is refused after that pass.
