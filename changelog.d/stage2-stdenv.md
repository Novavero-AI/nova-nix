- **`pkgs/windows` has a stdenv on the seed ladder's native toolchain, to replace the MSYS2 one: the seed stdenv's builder and tools, busybox-w32's sh and applets and `gnumake`, with the ladder's `binutils-native-x86_64` and `gcc-native-x86_64`, as `x86_64-windows`, and `pkgs/windows`' GNU Hello package builds with it unchanged.** Its builds reach the compilers and the linker through its `cc`, as nixpkgs' reach theirs through `stdenv.cc`: `gcc`, `cc`, `g++`, `c++` and `ld`, scripts that give every build what the stage-1 stdenv's wrapper gives its builds. The C drivers compile at `-std=gnu17` ahead of a package's own options, since GCC 16 defaults to C23, under which an empty parameter list declares a function that takes no arguments and the K&R declarations older gnulib copies carry conflict with the C library's; the C++ drivers keep the compiler's default. Every link a driver makes gets `--no-insert-timestamp` from a specs file appended to GCC's link spec, which the driver applies only when it links: the stage-1 wrapper's `-Wl,--no-insert-timestamp`, added to each command with no compile-only option, is an input file to the driver, so with it `gcc -v` goes on to link. `ld` gets the flag directly. Each driver runs with none of the variables GCC 16 searches directories from: `CPATH`, `C_INCLUDE_PATH`, `CPLUS_INCLUDE_PATH`, `COMPILER_PATH`, `LIBRARY_PATH`, `LPATH` and `GCC_EXEC_PREFIX`, the last three of which the stage-1 wrapper leaves set; the Objective-C variables it also unsets serve a language `gcc-native-x86_64` does not compile. The wrappers are scripts with no extension, which busybox's sh and GNU make run through the `sh` their first line names, and neither toolchain's `bin` directory is on `PATH`, since GNU make looks for a command with `.exe` in every directory of `PATH` before it looks for one without, and would run `gcc.exe` past the wrapper. `AR` names binutils' archiver by its path, since busybox's sh runs its own `ar` applet for the name. configure is told `--build=x86_64-w64-mingw32`, since `config.guess` cannot read busybox's `uname`, and the stdenv's `config.site` makes `-O2` the default `CFLAGS` and `CXXFLAGS` in place of configure's `-g -O2`, whose debugging information would name the build directory, which nova-nix makes in the store directory. CI's ladder gains a Stdenv stage after Native x86_64 on x64 and ARM64 Windows, which builds Hello with the stdenv, runs it and checks that it names neither the store directory nor its build directory, and builds a check whose programs, compiled and linked by each wrapper by name, by `gcc` with a package's own `-std` and from a make recipe, and by `ld`, report the standard they were compiled at and carry a zero time stamp, and in which none of those variables reaches the compiler, though each reaches `gcc-native-x86_64`'s own drivers. A test reads the closures: the one leaf the stdenv and its checks add to the native toolchain's is Hello's archive, neither stage-1 seed is in Hello's, and its builds run the seed stdenv's `setup.sh` with the applets, `gnumake` and the wrappers alone on `PATH`.
