- **`builtins.addErrorContext` keeps its value's failure when evaluating the message fails too, with a line naming the message's own failure, as upstream 2.36.0 does: `builtins.addErrorContext (throw "a") (throw "b")` fails with `b`, and a throw inside it stays catchable by `builtins.tryEval` whatever the message is.** The message's failure escaped in place of the value's, as it does up to 2.35.4. Upstream 2.36.0 rethrows the error it caught after evaluating the message, adding `while evaluating the error message passed to builtins.addErrorContext, another error occurred: ...` to its trace when that fails (`prim_addErrorContext` in primops.cc), so that the type of the value's failure, which decides whether `tryEval` catches it, is kept. nova-nix follows the newest pinned release.
- **Library API:** `MonadEval`'s `addErrorTrace` method is `addEvaluatedTrace`, which takes the line to give when making the line fails; `addErrorTrace` is a function of `Nix.Eval.Types` taking a line that is already made.
