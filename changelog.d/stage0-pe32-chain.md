- **`pkgs/windows` builds stage0-pe32's chain as derivations, from a 1,623-byte seed to hex0, hex1, hex2, catm, M0, cc_x86, M2-Planet, M1, hex2-new and kaem.** The Windows stdenv starts from prebuilt MSYS2 and MinGW-w64 packages, and this is the first part of a path that starts from source instead. Each derivation is one command of stage0-pe32's `x86/mescc-tools-mini.cmd`, its builder the link that command runs and its output the one file the command writes, the shape nixpkgs gives stage0-posix's chain in `minimal-bootstrap/stage0-posix/mescc-tools-boot.nix`. Each link is `stage0-pe32.<name>`, with M2-Planet as `M2` and kaem as `kaem-unwrapped`. The links are 32-bit PE, so each step is an `i686-windows` derivation, which x64 Windows runs through WoW64 and ARM64 Windows through its x86 emulator. Nothing in the chain runs `cmd.exe` or a shell, and nothing comes from the MSYS2 seed: its only inputs are the seed and stage0-pe32, M2-Planet, M2libc and mescc-tools at the commits stage0-pe32 pins, each fetched as GitHub's archive with `builtin:fetchurl` and unpacked with `builtin:unpack`. hex0 is fixed-output to the seed's own hash, as nixpkgs' is, so a seed that does not reproduce itself fails the build. CI builds the chain on x64 and ARM64 Windows, with the x64 nova-nix on both, and checks each link against the SHA-256 stage0-pe32's own CI records for the same commit.
