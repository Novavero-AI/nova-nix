- **Evaluation runs 1.7 to 2.4 times as fast and allocates 40 to 50% less: the evaluator is compiled for the monad `nova-nix` runs it in.** The evaluator in `Nix.Eval` is written over any `MonadEval`, and nothing compiled it for `EvalIO`, the monad the executable and `Nix.Eval.IO` run it in, so every bind and every class method in it was a call through the instance dictionary, which GHC can neither inline nor fuse. The library now builds with `-fspecialise-aggressively -fexpose-all-unfoldings`, and `Nix.Eval.IO` specialises `eval`, `deepForce` and `selectAttrPath` to `EvalIO`, exporting rules that send a call at `EvalIO` in any module to that code. The flags alone would leave the executable's own call of `eval` on the dictionary-passing evaluator, since `eval` is small enough to be inlined into `Nix.Eval.IO` rather than given a rule there. `EvalIO`'s actions are also built one-shot, the trick GHC's own `IOEnv` uses, so an action takes the evaluator state and the IO world as arguments instead of returning a closure that waits for them. On `profiling/stress.nix`, `fib 30`, two million three-level selects and two million `elemAt`s, best of five on an Apple M2, time falls from 0.81, 2.22, 2.34 and 5.21 s to 0.46, 0.93, 1.32 and 2.47 s, with the one-shot actions worth 8 to 12% of it, and the results are unchanged. A clean build of the library takes about 13% longer, 94 s where it took 83 s on the same machine, the executable and test suite about 7% longer, and the stripped executable is 2% larger. The evaluator's source stays polymorphic, and the test suite still runs it in its pure monad.
