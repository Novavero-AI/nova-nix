- **`builtins.fetchurl` names the file it fetches as upstream does: by its `name` attribute when one is given and not empty, and otherwise by the base name of the whole URL, a query or fragment included.** nova-nix ignored `name`, and named the file by the URL's last component with any query or fragment cut off, or `source` when that was empty, so `builtins.fetchurl { url = ".../f?x=y"; sha256 = ...; }` and any fetch given a `name` had another store path than upstream's. Upstream's `fetch` (fetchTree.cc, the same at 2.24.9, 2.34.9 and 2.36.0) reads `name` with the other arguments, and when it is empty takes `baseNameOf` of the URL, which drops trailing slashes and keeps everything after the last one, so a URL ending in `/` is named by the component before it.
