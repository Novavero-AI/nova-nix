- **A chain of `//` merges its operands from the first, as upstream 2.34's update queue does: `a // b // c` layers `b` on `a` and then `c` on that, where it made `b // c` first and merged `a` with it.** `//` groups to the right, so a chain parses as `a // (b // c)`. Upstream 2.34 gathers a chain's operands, descending only into an operand that is itself an update, and once it has evaluated them all folds them into one set from the leftmost (eval.cc:1991-2029 at 2.34.9), so a chain of small sets on a large one copies the small ones alone, once each. The operands are still evaluated first to last, as 2.24.9 evaluates them, where 2.34 evaluates them last to first, so the operand a failure comes from is unchanged, and a chain one of whose operands fails merges none. Over the first 5,000 attributes of the memory suite's walk of nixpkgs 26.05, `//` copies 51,920,625 entries, where upstream 2.34.9 copies 51,920,548 (`nrOpUpdateValuesCopied`).
