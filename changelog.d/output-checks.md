- **A build's output that its group or anyone else may write is refused, every output is made canonical before it is read or changed, and a fixed output is replaced by a fresh copy of itself before it is hashed, as upstream's are.** Upstream refuses such an output with `suspicious ownership or permission on '...' for output '...'; rejecting this build output`, since someone other than the build may have changed it, then makes the output canonical, so nothing in it is setuid, or open to another user's write or swapped link, while it is rewritten and scanned (`registerOutputs`, local-derivation-goal.cc:2333-2351 at 2.24.9). nova-nix made an output canonical only once it was placed. A fixed output's fresh copy leaves behind the inode the builder wrote, so a descriptor the builder passed out of its build cannot change what is registered (2594-2600); the copy is made canonical in its turn, and it is the copy that is scanned and hashed. A fixed output that references a store path, itself included, is refused with upstream's `illegal path references in fixed-output derivation '...'` (2623-2625), which nova-nix let through; upstream registers such an output under the path its references give it before it fails the build, and nova-nix registers nothing, as for a hash mismatch. On Linux an output's extended attributes, ACLs among them, are removed as it is made canonical, as upstream removes them (posix-fs-canonicalise.cc:71-91), but for the three upstream's `ignored-acls` keeps by default, `security.selinux`, `system.nfs4_acl` and `security.csm`. A directory in an output that its owner may not search is given search before it is read, so it ends at 0555 where upstream's canonicalisation gives it 0444 and a single-user upstream build, not run as root, then fails to read beneath it. A hash rewrite of an output's file opens it without following a link, and refuses one swapped in. An output holding a node another user owns is refused with upstream's `invalid ownership on file '...'` (posix-fs-canonicalise.cc:95-107) before it is made canonical, which would change that node, a hard link into the output among them. An output that is a symlink is there whatever it names, as upstream reads it with `lstat` (2326), where nova-nix took one naming nothing for a missing output. nova-nix now runs with upstream's file-creation mask, 0022, as every upstream command does (`initNix`, shared.cc:172-175): everything it creates is made under it, the store and its database, push and fetch caches, garbage-collector roots and out-links among them, and so is everything a builder it starts creates, so no ordinary build's output is refused.
- **Library API:** `Nix.Store` exports `useStoreFileMask`, which a program building through the library calls to give its builders upstream's mask, `replaceWithCopy` and `freshCopyPath`, and, for testing, `rewriteRegularFile`; and `Nix.Store.Metadata` exports `writableByOthers` and `foreignOwnedNode`.
