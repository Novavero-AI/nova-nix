- **`__curPos` evaluates to the position it is written at, `{ column; file; line; }` in a file and `null` in an `--expr` argument, where it failed with `undefined variable '__curPos'` when forced.** Upstream's parser reads the identifier as a position, never as a variable, wherever it is an expression (`expr_simple`, parser.y:276-280 at 2.24.9), and `ExprPos::eval` answers `EvalState::mkPos` of it (eval.cc), the set `builtins.unsafeGetAttrPos` gives for an attribute: the file's path as a string and the line and column of the identifier, or `null` for text with no file behind it. The parser here now does the same, so no binding of the name reaches it: `let __curPos = 1; in __curPos` is the position, as it is upstream, where it was `1`, and so is `__curPos` under a function whose argument is named `__curPos` or a `with` whose set has that attribute. `inherit __curPos;` copies a variable, as upstream's `inherit` builds one without that check, so with nothing binding the name it fails as an undefined variable before anything is evaluated, where it failed only when the attribute was forced. nixpkgs' Firefox wrapper sets `pos = __curPos;`, so `firefox-bin` failed to evaluate. The position differs from upstream's where `unsafeGetAttrPos`'s does: the file of a file outside the store reached through a symlinked directory is its path with every symlink resolved, where upstream's is the path as written.
