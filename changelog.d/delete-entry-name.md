- **The library's checked delete refuses a name that is not one entry of the store directory, where it removed a path outside the store, the store directory itself or the store's metadata directory.** `deleteStorePathRaw` and `deleteStorePaths` joined the name they were given to the store directory, and that join keeps an absolute name as it is and follows `..`, so `/etc/x` or `../x` passed the liveness check, found no registration row and was removed as a tree without one, with a lock file left beside it. The empty name joined to the store directory itself, `.` to everything in it, and `.nova-nix` named the metadata directory that holds the store's database and roots. Such a name is now refused before the delete takes a lock or looks for a tree: the empty name, a `/` or a `\`, a dot-leading name, a `:` and a NUL, which are the rules `store delete` already applied to the last component of each argument, with the separators and NUL added. Upstream's delete is never handed a name: `nix-store --delete` resolves each argument to a store path first (`opDelete` and `GCOptions::pathsToDelete`, a `StorePathSet`, at 2.24.9). `store delete` refuses what it refused before; its refusal of an empty name no longer repeats the argument.
- **Library API:** `deleteStorePathRaw` takes a `StoreEntryName` where it took `Text`, as `deleteStorePaths` does. `Nix.Store.GC`, which `Nix.Store` re-exports, adds `StoreEntryName` without its constructor, `storeEntryName :: Text -> Either Text StoreEntryName`, the only way to make one, and `storeEntryNameText`. `resolveDeleteTarget` returns a `StoreEntryName`.
