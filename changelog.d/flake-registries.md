- **`registry list` and `registry resolve` read the flake registries as upstream 2.36.0 reads them, and print what `nix registry list` and `nix registry resolve` print.** The user's registry is `nix/registry.json` under the config home `nix.conf` is read from, the machine's is `registry.json` in `NIX_CONF_DIR`, and the global one is the file or URL the `flake-registry` setting names: upstream's `https://channels.nixos.org/flake-registry.json` by default, downloaded with upstream's retries, and none when the setting is empty. A registry file is version 2, a `dir` among an entry's `to` attributes is the reference's, and an entry that cannot be read is warned of in upstream's `cannot read flake registry` or `cannot parse flake registry` words, the entries before it kept. A lookup follows upstream's `lookupInRegistries`: the first entry, registry by registry and each in file order, that matches replaces the reference, an `exact` one only for a reference equal to its own and another passing on the `ref` and revision it does not set, until no entry matches, with upstream's refusals of a reference no entry maps, of a cycle, and of an override a scheme cannot take. Upstream adds the downloaded global registry to the store and roots it; nova-nix reads it in memory, and downloads it again for each command.
- **Library API:** the new module `Nix.Fetch.Registry` reads registries and looks references up; `Nix.Fetch.Input` exports `sameInput`, `inputContains`, `inputIsDirect`, `inputRef`, `inputRevision` and `applyOverrides`, and `Nix.Fetch.Download` `urlSource`. `NixConfig` has a field `ncFlakeRegistry`.
