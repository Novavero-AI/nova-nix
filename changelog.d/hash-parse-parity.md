- **Hash strings are parsed as upstream's `Hash::parseAny` and `Hash::parseSRI` parse them, so `builtins.convertHash` refuses a tag that disagrees with `hashAlgo`, a fixed-output derivation whose `outputHashAlgo` names no algorithm upstream knows takes its algorithm from `outputHash`'s tag, and `builtins.fetchGit` accepts a `narHash` that spells the fetched hash with text after its padding.** Five cases differed from upstream 2.24.9. A base16 or nix32 digest that did not decode failed with `hash '...' is not a valid base16 sha256 hash`, where upstream's `Hash` constructor reports `invalid base-16 hash '...'` and `invalid base-32 hash '...'` (hash.cc:214, :232, :242). An unknown algorithm, in `builtins.hashString`, `builtins.hashFile`, `builtins.convertHash` or a hash's tag, failed with `unknown hash algorithm '...'`, the first two after the builtin's name, and without the `, expect 'md5', 'sha1', 'sha256', or 'sha512'` upstream's `parseHashAlgo` adds (hash.cc:441). `builtins.convertHash` ignored `hashAlgo` when the hash carried a tag; upstream parses `hashAlgo` first and hands it to `Hash::parseAny` (primops.cc:4100-4108), so an unknown `hashAlgo` is refused whatever the hash, and a tag that names another algorithm fails with `hash '...' should have type '...'` (hash.cc:193-194). A fixed-output derivation refused an `outputHashAlgo` it did not know; upstream reads it with `parseHashAlgoOpt` (primops.cc:1352), which gives no algorithm for a name it does not know, so `outputHash`'s own tag decides, and an untagged hash fails with `hash '...' does not include a type, nor is the type otherwise known from context` (hash.cc:191-192), as an untagged hash given to `builtins.convertHash` without `hashAlgo` now does too. A known `outputHashAlgo` that disagrees with the tag is still refused, as upstream refuses it. `builtins.fetchGit` compared a declared `narHash` with the fetched one as text; upstream reads it with `Input::getNarHash` (fetchers.cc:324-333) before fetching anything, as an SRI hash that must be SHA-256 or as the empty string for a digest whose every byte is zero, and compares the hashes (fetchers.cc:214-222), so a spelling with text after its `=` matches, a prefixed one fails with `hash '...' is not SRI`, a SHA-512 one fails with `narHash must use SHA-256`, and a mismatch names the pin in SRI. The refusal of a tag that disagrees with the algorithm the context expects is upstream's `hash '...' should have type '...'` for `outputHash` and for the `sha256` of `builtins.fetchurl`, `builtins.fetchTarball` and `builtins.path` too, where it added the tag's own algorithm and a `derivation:` or builtin's name.
