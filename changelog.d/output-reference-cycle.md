- **A build whose outputs reference each other in a cycle fails with upstream's message, `cycle detected in build of '/nix/store/...-foo.drv' in the references of output 'dev' from output 'out'`, and registers none of them.** Both outputs used to register, each naming the other, which left a reference cycle that upstream's own registration refuses (`registerValidPaths`, local-store.cc at 2.24.9) and a pair of paths neither of which could be deleted alone, since each had a referrer. Upstream scans every output first, orders the outputs so that each follows the siblings it references, and fails the build on a cycle before any output is registered (`registerOutputs`, local-derivation-goal.cc, and `topoSort`, topo-sort.hh). The ordering here is upstream's depth-first walk, so the outputs are placed in upstream's order and a cycle is reported through the same two outputs upstream names. A self-reference and a one-way reference between outputs still build. An output registered before the build, as in a partial rebuild, counts as referencing nothing, as upstream counts it, so a rebuilt output may reference it whatever its discarded copy references.
- **Library API:** `Nix.Builder.buildDerivation` and `Nix.Realise.RealiseEffects`' `reBuild` take the derivation's `.drv` path after the derivation, and `Nix.Builder` exports `orderByReferences` and `ReferenceCycle`.
