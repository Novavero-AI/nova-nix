- **`nova-nix build --check` builds a derivation again beside its valid outputs and fails when one comes out different, as `nix-build --check` does.** A path that came from a binary cache was only ever trusted; a check holds it to a build. The rules are those of upstream's build mode `bmCheck` at 2.24.9. The mode covers the derivation the build was asked for and no other: its inputs are substituted or built as ever (`DerivationGoal::gaveUpOnSubstitution` gives each input's goal `bmNormal`), since the rebuild needs them and a path that was substituted never fetched them. An output that is not valid is substituted first, as under any mode, and a derivation still short of an output stops with upstream's `some outputs of '<drv>' are not valid, so checking is not possible`, before any input is looked at (`outputsSubstitutionTried`). The derivation itself is then built here and never substituted. Its builder writes each output to a scratch path while the valid one stays where it is, the scratch path's hash is rewritten to the output's own in what the builder wrote, so that an output holding its own path or a sibling's compares equal, and the NAR hash of the result is compared with the one the store recorded, which is all upstream compares (`registerOutputs`, local-derivation-goal.cc). The first output that differs stops the check with upstream's `derivation '<drv>' may not be deterministic: output '<path>' differs`, after nova-nix's own `build failed (exit 104):`, and the command exits with upstream's status for it, 104 (`Worker::failingExitStatus`), so a caller can tell it from a build that broke; every other failure still exits 1, where upstream's status for a failed builder is usually 100. Whatever the comparison finds, the rebuild registers nothing, the outputs it is compared with are as they were, and what it wrote is removed; the substitutions and builds before it add to the store as in any build. A fixed output is held to its declared hash first, and a reference cycle between the rebuilt outputs fails a check as it fails a build. A check that passes is logged as `[check]`. Five things differ from upstream. Its `keep-failed` and `run-diff-hook` settings, which keep the rebuilt output as `<path>.check` and name it in the error, are not implemented, so the rebuilt output is always discarded. It marks a path it has checked as ultimately trusted and signs it; nova-nix's store database records neither. A check here wants every output of the derivation valid, because a build here realises them all, where upstream's wants only the outputs the build asked for, which for `nix-build` is the one it prints. nova-nix builds without a sandbox, so it checks as upstream does outside a Linux sandbox, through the scratch path and the rewrite: an output that holds its own path where a rewrite of the hash cannot reach it, compressed for one, differs under a check here, as it does under upstream's on macOS, and not under upstream's in a Linux sandbox, which builds at the output's own path inside a chroot. And a builder is handed its output under the directory its store's files are in, as before, where upstream builds a store kept outside its own directory only in a Linux chroot that shows it there: an output that records its whole path therefore checks equal here only against one built in a store kept in the same directory. - **Library API:** `Nix.Realise.RealiseSettings` gains `rsMode`, a `BuildMode` that is `BuildNormal` or `BuildCheck`; `RealiseEffects` gains `reCheck`, which answers a `CheckVerdict`; `Realised` gains `Checked`; and `RealiseFailure` gains `OutputsNotValid`, `NotDeterministic` and `MissingDerivation`, the last for a check whose root the graph does not hold, which is a failure where a build of such a root realises nothing and succeeds. A record built without a default needs the new field, and a total match the new constructors. `realiseFailureMessage` takes the directory the store's files are in before the failure, to name the output that differs where it is, and `realiseFailureStatus` gives the status a failure exits with. `BuildConfig` gains `bcMode`, and `buildWithDeps` answers a `BuildFailure` with that status, 104 for a check that found a difference, where it answered 1 for every failure. `Nix.Builder` exports `checkDerivation`, the rebuild and comparison alone for a derivation whose outputs are valid and whose inputs are realised.
