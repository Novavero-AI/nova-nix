- **`pkgs/windows` builds TinyCC's bootstrappable rounds on the Mes rung: `tinycc.boot0` to `tinycc.boot3` and `tinycc.bootstrappable`, each tcc compiled by the round before it and each compiling the Mes C library the next links with.** They are nixpkgs' `minimal-bootstrap/tinycc` rounds with the options janneke's `boot.sh` gives each, the last repeating boot3's so that its floating point is compiled by a tcc that has it. Three things differ from nixpkgs besides the first round's changes for PE. tcc.c is compiled with `_WIN32` undefined and `__windows__` defined: a PE tcc predefines `_WIN32`, which tcc.c reads as a host with the Win32 API and answers by including `windows.h`, where these tccs run on Mes libc as `tinycc-boot-mes` does, and `__windows__` tells Mes's `fcntl.h` the system in its place. Each round names `crt1.o`, libc and libtcc1 when it links, since a PE tcc adds no startup file or C library of its own and links msvcrt and kernel32 unless told `-nostdlib`. And each round's `tcc.exe` is marked executable by its script, since tcc's PE writer marks nothing. CI builds every round from the seed on x64 and ARM64, runs the last with `-version`, and runs a hello and a program printing the two words of a double it computes, both compiled and linked by the last, checking what each prints and the status it exits with. `printf`'s `%f` is no check at these rounds: Mes's `dtoab` casts the double to `long`, which this tcc compiles as a call to `__fixdfdi`, and Mes's `libtcc1.c`, which nixpkgs copies over TinyCC's for the rounds, stubs it to 0.
