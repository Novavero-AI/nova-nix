- **`pkgs/windows` builds mescc-tools-extra's thirteen programs from stage0-pe32's links, as `stage0-pe32.mescc-tools-extra.<name>`: sha256sum, match, mkdir, untar, ungz, unbz2, unxz, catm, cp, chmod, rm, replace and wrap.** nixpkgs builds them with M2-Mesoplanet in `minimal-bootstrap/stage0-posix/mescc-tools-extra/build.kaem`, and M2-Mesoplanet has no Windows target. Here one function in the stage0-pe32 package set turns a program's name, sources and C library files into the five steps stage0-pe32's `x86/mescc-tools-mini.cmd` gives kaem: M2-Planet with `-D __windows__=1`, catm, M0, catm and the hand-written hex2, each its own `i686-windows` derivation. M2-Planet reads no `#include` line, so each program's M2libc files are what its `#include` lines reach on the M2libc fork's `x86/windows` target, listed in the package. hex2-new and kaem are built by the same function, and their derivations are unchanged. The sources are upstream's mescc-tools-extra at d1d8146, the commit stage0-pe32 pins. CI builds all thirteen on x64 Windows and runs each on small committed fixtures. On Windows, untar stops at a symlink unless given `--non-strict`, because the port's `symlink` always fails; chmod changes nothing and succeeds; `mkdir -p` and cp's copy into a directory split paths on `/` only; replace needs `--output`, because its default `/dev/stdout` does not exist; and wrap stops at its first mount, which the port's `mount` always refuses.
