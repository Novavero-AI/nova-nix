- **Library API:** the new module `Nix.Store.Ops` gives the store a command works against as a record of its operations, `StoreOps`: adding what an evaluation wrote or named, an `EvalObjects` of its sources, written trees and derivations, references first (`soAddEvalObjects`); realising several derivations, each for the outputs a request names (`soBuild`); checking one derivation, every output of it, as `nova-nix build --check` does (`soCheck`); and rooting an out-link (`soAddOutLinkRoot`). `withLocalStore` runs an action with the operations of the store in a `BuildConfig`'s `bcStoreDir`, which it opens at the first operation and closes once, when the action ends; an add, a build or a check in a store upstream Nix's database manages is refused before the store is opened, since opening it would make this store's database there. `withOpenedOnFirstUse` is the bracket it opens the store with. `nova-nix build` adds, builds or checks, and roots through these operations. `Nix.Builder` exports `buildRequests`, which reads the requested derivations and their inputs from the store and realises them through `Nix.Realise.realiseRequests`, `checkStored`, which reads one derivation from the store and checks it as `buildWithDeps` does under `BuildCheck`, and `BuildStop`, the message and status of a stopped build. `Nix.DependencyGraph` exports `buildDepGraphFrom`, the graph of several roots read as their inputs are.
