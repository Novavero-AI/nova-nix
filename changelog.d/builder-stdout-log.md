- **A builder's standard output reaches the build log with its standard error, in the order the builder wrote them, and `build` prints each line on stderr as it completes.** Standard output was discarded, and standard error was held until the builder exited and then shown only inside a failure message. Upstream hands the builder one channel for both, its standard output a copy of its standard error (`commonChildInit`, child.cc at 2.24.9), and its default logger prints every build-log line to stderr as it arrives (`SimpleLogger`, logging.cc). `nix-build` keeps that logger, so it shows the whole log while the build runs and adds no `log-lines` tail to the failure (derivation-goal.cc), and a failed builder's `BuildFailure` is now `builder failed`, with its output in the log rather than the message. Lines follow upstream's discipline (`DerivationGoal::handleChildOutput`): a carriage return returns to the start of the line, so a Windows program's CRLF ends a line without its CR and a progress counter redrawn after CRs leaves its last state, and an unterminated last line is flushed when the output ends. Upstream's channel is a pseudoterminal and this one is a pipe, which `System.Process` offers on Windows as well as POSIX, so a program that line-buffers or colours its output only on a terminal block-buffers and stays plain here. On POSIX both ends of the pipe are close-on-exec, so the builder holds it only as its standard output and standard error, as upstream's child does after `closeMostFDs`, and a daemon that closes those lets the build finish. Each line is filtered as upstream's logger filters it (`filterANSIEscapes`, terminal.cc): a tab becomes spaces to the next multiple of eight columns, a bell is dropped, and an escape sequence is dropped, except that colour (an SGR sequence) is kept on a terminal whose `TERM` is set and not `dumb` with neither `NO_COLOR` nor `NOCOLOR` set (`isTTY`), so a builder cannot move the cursor, clear the screen or set the title of the terminal running the build. A line stderr fails to take is dropped and the build goes on, as upstream's `writeToStderr` ignores a failing write, so a closed reader of stderr does not fail the build. Upstream reads a line beginning `@nix ` as a JSON log message and does not print one that parses (`handleJSONLogMessage`); here every line is printed, and since nova-nix sets no `NIX_LOG_FD`, where upstream sets it to 2, nixpkgs' stdenv writes no such lines. Upstream also keeps the log in a file that `nix log` reads back (`keep-build-log`); nova-nix keeps none.
- **Library API:** `Nix.Builder.BuildConfig` gains `bcBuildLog`, the handle a builder's output is written to, which `defaultBuildConfig` sets to stderr. The new module `Nix.Builder.Log` holds the line discipline (`PendingLine`, `emptyPendingLine`, `feedBuildLog`, `endBuildLog`), the terminal filter (`EscapeFilter`, `filterLogLine`) and the streaming around them (`openLogPipe`, `streamBuildLog`).
