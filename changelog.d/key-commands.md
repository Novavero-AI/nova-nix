- **`nova-nix key generate-secret --key-name NAME` prints a new Ed25519 secret key for signing a binary cache, and `nova-nix key convert-secret-to-public` prints the public key of the secret key on stdin, byte for byte as upstream's `nix key` commands do.** A cache `push` writes to a directory is signed with a secret key file, and nova-nix had no way to make one: the reference pointed at upstream's `nix-store --generate-binary-cache-key`. The secret key is `NAME`, a colon and the base64 of 64 bytes, a seed from the system's source of randomness and then that seed's public key, as libsodium makes the key upstream prints, with no line feed after it. The public key is the secret key's last 32 bytes under the same name, read off as upstream reads it rather than derived from the seed again, also with no line feed. Stdin is read whole and as it is, as upstream reads it. The base64 is read up to its first `=`, skipping line feeds, so a key echoed with a line feed after it is read, and what follows a padded key is not read at all. A character outside base64 before the padding is refused with upstream's report: an `error:` line, the trace `while decoding key named ''` after an ellipsis on the next, and `error: invalid character in Base64 string: '...'` below it, each line indented by the width of `error: `. A key with no colon, no name or no bytes is refused the same way, with `error: key is corrupt`, and a key that is not 64 bytes with `error: secret key is not valid` alone. Each refusal exits with status 1. The name is the bytes the command line gives, unchecked, as upstream takes it, and the last `--key-name` given wins. Without one the command is refused with upstream's `required argument '--key-name' is missing`. Both commands take `--store` and leave it unused, as upstream's take that setting as every command does.
- **Library API:** `Nix.Key` reads, makes and spells signing keys, and `Nix.Daemon.Protocol` reads and spells signatures through `Nix.Key`'s `parseColonBase64` and `renderColonBase64`, so a byte outside base64 that is not ASCII in a signature the daemon receives is named as the character of its value, where it was named as the UTF-8 character it began.
