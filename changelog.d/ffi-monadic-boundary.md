- **Evaluation is faster and allocates less, and every read of and allocation in the C data layer runs where the evaluation reaches it: the evaluator reaches C through actions of its own monad.** Thunks, environments, attribute sets, lists, lambdas and the bytecode live in C, and the evaluator reached them through functions that looked pure and made their C call under `unsafePerformIO` whenever GHC demanded the result. Each read of an instruction's field built a lazy thunk and paid `unsafePerformIO`'s duplication check, and an allocation ran whenever its result was first needed rather than where the evaluation made it, which no collector of C memory can work with: a cell made at an unknown moment cannot be assigned to the force or call that made it. Every read, write and allocation is now an action of `MonadCData`, which every `MonadEval` has, so in the executable each one is a direct FFI call at its point in the evaluation. Three reads stay outside a monad, each in `Nix.Eval.CData` with the invariant that makes it sound: an interned symbol's bytes, which do not change once interned and are copied while no intern runs; the `Show` and `Eq` instances of the C handles, which no evaluation result depends on; and a whole computation run as a value, which is how the pure test evaluator runs and how the `derivation` constant and the builtin functions' values, which GHC already shared, and the empty list's cell are made once for the process. On `profiling/stress.nix`, `fib 30`, two million three-level selects and two million `elemAt`s, best of five on an Apple M2, time falls from 0.54, 1.03, 1.59 and 3.07 s to 0.44, 0.58, 1.13 and 2.25 s and allocation from 2.43, 6.68, 8.08 and 13.07 GB to 1.86, 3.49, 5.48 and 8.15 GB, and two results change, each to upstream's, because the calls behind them now run where the evaluation reaches them; each has an entry of its own. A variable lookup that would read a slot its frame has not filled yet, which only a defect in the resolver or the frame builder makes, raises `CInvariantViolated` naming `nn_env_lookup_resolved` where it handed on a NULL cell that faulted at its first force.
- **Library API:** `MonadEval` has `MonadCData` (in the new `Nix.Eval.CData`) as a superclass, so an instance needs `liftCData`, which runs a `CData` action; `IO` is an instance. The C accessors and allocators are `MonadCData` actions where they were pure: in `Nix.Eval.Types` the attribute set, list, environment and thunk functions (`attrSetLookup`, `attrSetFromMap`, `evaluated`, `readThunkValue`, `mkThunkBc`, `buildCSlots`, `tieFrame`, `newCEnv` and the rest), `Nix.Eval.CList`'s `clistFromThunks`, `clistThunks`, `clistLen`, `clistIndex` and `clistDrop`, `Nix.Eval.SourcePos.lookupPos`, `Nix.Eval.Print.printValue` and `printAmbiguous`, `Nix.Eval.deferApply`, and `Nix.Builtins`'s `builtinEnv`, `builtinEnvWithScope`, `parseNixPath` and `searchPathRoots`; the accessors of the C binding modules (`Nix.Eval.CThunk`, `CAttrSet`, `CEnv`, `CLambda`, `CCtxStr`, `CBytecode`) and `Nix.Eval.Symbol.symbolIntern` are too, so their `IO` callers are unchanged, and so are `Nix.Eval.Types.firstInSymbolOrder` and `Nix.Eval.EvalFormals.lambdaNameSymbol`, which intern; each environment and set constructor keeps the site it takes first, and `buildCaptureEnv` takes one too. `attrSetMapWithKey` and `tieFrame` take actions where they took functions, `Nix.Eval.CEnv.cenvEmpty` is a value, and `Nix.Eval.evalParsed` takes the action that builds the environment, which it runs once the source has compiled, and `Nix.Eval` exports `compileSource`; `Nix.Eval.IO.newEvalState` builds the `NIX_PATH` entries it reads as it runs, interning their strings then rather than when an entry is first used, so with `NIX_PATH` set it runs between `arenaInit` and `arenaDestroy`; `Nix.Eval.IO.newEvalStateWith` takes the search path instead, for a caller that builds its own, and `Nix.Eval.IO.nixPathValue` reads `NIX_PATH`'s bytes. `Nix.Eval.Types` no longer exports the unused `attrSetUnionWith`, `pushWithScope` and `lookupWithScopes`, nor `checkedCPtr`, which `Nix.Eval.CStatus` exports; it exports `compile`, `compileSource`, `readComputed`, `pendingCode`, `pushLazyWithScope`, `buildCaptureEnv`, `withScopeAt` and `resolveWithScopeAt`.
