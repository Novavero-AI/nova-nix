- **Evaluation is faster and allocates less, and every read of and allocation in the C data layer runs where the evaluation reaches it: the evaluator reaches C through actions of its own monad.** Thunks, environments, attribute sets, lists, lambdas and the bytecode live in C, and the evaluator reached them through functions that looked pure and made their C call under `unsafePerformIO` whenever GHC demanded the result. Each read of an instruction's field built a lazy thunk and paid `unsafePerformIO`'s duplication check, and an allocation ran whenever its result was first needed rather than where the evaluation made it, which no collector of C memory can work with: a cell made at an unknown moment cannot be assigned to the force or call that made it. Every read, write and allocation is now an action of `MonadCData`, which every `MonadEval` has, so in the executable each one is a direct FFI call at its point in the evaluation. Two reads stay outside a monad, each in `Nix.Eval.CData` with the invariant that makes it sound: an interned symbol's bytes, which do not change once interned and are copied while no intern runs, and a whole computation run as a value, which is how the pure test evaluator runs. The `Show` and `Eq` instances of the C handles read no C memory: two thunks, sets, lists or environments are equal when they are one C object, and each shows as its address. On `profiling/stress.nix`, `fib 30`, two million three-level selects and two million `elemAt`s, best of five on an Apple M2, time falls from 0.54, 1.03, 1.59 and 3.07 s to 0.44, 0.58, 1.13 and 2.25 s and allocation from 2.43, 6.68, 8.08 and 13.07 GB to 1.86, 3.49, 5.48 and 8.15 GB, and two results change, each to upstream's, because the calls behind them now run where the evaluation reaches them; each has an entry of its own. A variable lookup that would read a slot its frame has not filled yet, which only a defect in the resolver or the frame builder makes, raises `CInvariantViolated` naming `nn_env_lookup_resolved` where it handed on a NULL cell that faulted at its first force.
- **Library API:** `MonadEval` has `MonadCData` (in the new `Nix.Eval.CData`) as a superclass, so an instance needs `liftCData`, which runs a `CData` action; `IO` is an instance. The C accessors and allocators are `MonadCData` actions where they were pure: in `Nix.Eval.Types` the attribute set, list, environment and thunk functions (`attrSetLookup`, `attrSetFromMap`, `evaluated`, `readThunkValue`, `mkThunkBc` and the rest), `Nix.Eval.CList`'s `clistFromThunks`, `clistThunks`, `clistLen`, `clistIndex` and `clistDrop`, `Nix.Eval.SourcePos.lookupPos`, `Nix.Eval.Print.printValue` and `printAmbiguous`, `Nix.Eval.deferApply`, and `Nix.Builtins`'s `builtinEnv`, `builtinEnvWithScope`, `parseNixPath` and `searchPathRoots`; the `IO` accessors of the C binding modules (`Nix.Eval.CThunk`, `CAttrSet`, `CEnv`, `CLambda`, `CList`, `CCtxStr`, `CBytecode`), `Nix.Eval.Compile`'s `decodeBcFormals`, `decodeBcCaptureInfo` and `decodeBcBindings`, and `Nix.Eval.Symbol.symbolIntern` are too, so their `IO` callers are unchanged; each environment and set constructor keeps the site it takes first, and `buildCaptureEnv` takes one too. `attrSetMapWithKey` takes an action where it took a function, `Nix.Eval.CEnv.cenvEmpty` is a value, and `Nix.Eval` exports `compileSource`; `NIX_PATH`'s entries are built and interned as a session starts rather than when an entry is first used, and `Nix.Eval.IO.nixPathValue` reads `NIX_PATH`'s bytes. `Nix.Eval.Types` no longer exports the unused `lookupWithScopes`, nor `checkedCPtr`, which `Nix.Eval.CStatus` exports; it exports `compile`, `compileSource`, `readComputed`, `pushLazyWithScope`, `buildCaptureEnv`, `withScopeAt` and `resolveWithScopeAt`. `Eq` on `Thunk` and `AttrSet` compares identity, as on `Env` and `CList`, where it compared what they held, so two `NixValue`s holding equal sets in different C objects are unequal; `Show` on the four gives the address. `Nix.Eval.CEnv.cenvSlotCount` is gone, and so is `Nix.Eval.Types.thunkSameRef`, which `==` on `Thunk` now is. `Nix.Eval.CData` exports `cdataIO`, which runs a binding's `IO` action as a `CData` one, `runCData`, which runs a `CData` action in `IO`, and the two reads outside a monad, `readImmutable` and `runCDataPure`; `Nix.Eval.Operator` exports `expectedFailure`, upstream's refusal of a value of the wrong type.
