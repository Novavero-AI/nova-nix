- **An empty attribute set is one shared set wherever upstream shares one, and `//` with an empty operand gives the other operand's set, so neither allocates a set.** Upstream's `allocBindings` answers a size of 0 with its one `emptyBindings` (attr-set.cc), which `{ }` and every builtin that sizes its result by what it holds then hold, and `ExprOpUpdate::eval` copies the other operand's value when one is empty (eval.cc). nova-nix allocated a new set for each, and over the first 2,000 attributes of nixpkgs 24.11 the census counted 2,167,080 of its 5,815,653 sets as built empty or as an update with an empty operand (#530). Of the sets nova-nix makes, upstream sizes three before it knows they hold nothing, and gives each bindings of its own: `removeAttrs` of every attribute of a set (`prim_removeAttrs` in primops.cc), `intersectAttrs` of two sets with attributes and no name in common (`prim_intersectAttrs`), and a literal whose every name is a null `${...}` (`ExprAttrs::eval` in eval.cc); each is a set of its own here too. Both printers enter a set by its bindings (`Printer::printAttrs` in print.cc, `printAmbiguous` in print-ambiguous.cc), so these identities show where a value is printed: `let a = { x = 1; }; in [ a (a // { }) ]` prints the update as upstream's repeated marker under `nova-nix eval --strict`, where it printed the set twice, and an error or trace message prints each of the three empty sets of their own in full after the shared one, where it printed it as the marker. The census counts no shared set, and counts as shareable only a set made equal to one that already exists where upstream makes none, so the three are not.
- **Library API:** `Nix.Eval.Types` exports `emptyAttrSet`, the shared set. `attrSetFromMap`, `attrSetFromEntries` and `attrSetRemoveKeys` give `emptyAttrSet` for an empty result, except a removal from a set with attributes, which makes a set of its own. `Nix.Eval.CAttrSet` exports `cattrsetEmpty`, and `cattrsetInsert` raises on a frozen set, the shared one among them.
