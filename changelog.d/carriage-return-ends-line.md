- **A carriage return ends a line, as upstream's does: a `#` comment ends at the first CR or LF, and an LF, a CRLF and a bare CR each end one line in every position the lexer gives.** A comment ran to the next LF, so in a file with bare CR line endings it swallowed the code after it, and positions ended a line at a bare CR only where a double-quoted string reads it as an LF, so `builtins.unsafeGetAttrPos` and parse errors put what followed any other bare CR on the wrong line. Upstream's line comment is `\#[^\r\n]*` (lexer.l at 2.24.9) and its position table splits a source at an LF, a CRLF or a bare CR (`Pos::LinesIterator`, position.cc), and both now hold here for whitespace, comments, both kinds of string, their escapes, and the position of a malformed UTF-16 source's error. A string's value is unchanged: a double-quoted string still reads a raw CR or CRLF as an LF, and an indented string keeps its CRs. A syntax error at the end of input after a trailing line comment stands past the comment, at the end of input as upstream reports it (`yyerror`, parser.y), where it stood at the `#`.
- **Library API:** `Nix.Parser.Lexer` exports `positionAfter`, the line and column `tokenize` gives the end of a source.
