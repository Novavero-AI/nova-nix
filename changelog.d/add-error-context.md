- **`builtins.addErrorContext` adds its message to the trace of a failure inside it, which `nova-nix eval` prints above the error, and forces the message only when its value fails.** It returned its second argument and added nothing, and it forced both arguments as it was applied, so `builtins.addErrorContext "ctx-marker" (throw "x")` reported `error: x` alone where nix-instantiate prints a line of context, `ctx-marker`, above it, and `builtins.addErrorContext (throw "a") 1` failed with `a` where upstream gives `1`. Upstream's `prim_addErrorContext` forces the value inside a `catch`, and only there coerces the message, as a string, a path or a set with `__toString` or `outPath`, without copying a path into the store, then adds it to the failure's trace and rethrows the failure (primops.cc at 2.24.9), and nova-nix now does the same. The failure keeps its kind, so a throw inside stays catchable by `builtins.tryEval`, and nested contexts are listed outermost first. A message that fails itself, by throwing or by not coercing, fails in place of the value, as an exception thrown inside upstream's `catch` replaces the one caught, so `builtins.tryEval (builtins.addErrorContext 1 (throw "x"))` fails with `cannot coerce an integer to a string: 1` rather than catching the throw. An empty message adds no line of its own, as upstream's `showErrorInfo` passes over a trace whose text is empty (error.cc). The parity job compares the line of context `ctx-marker` adds with nix-instantiate's.
- **Library API:** `Nix.Eval.Types.MonadEval`'s `addErrorTrace` takes its line as an action, `m Text`, run only when the action it wraps fails, where it took a `Text`; a constant line is `pure line`. An instance runs the line when the action fails and lets a failure of the line escape in place of the action's.
