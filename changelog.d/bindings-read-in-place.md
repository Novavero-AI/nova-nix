- **A set, a `let` and a function allocate less and evaluate faster: their bindings and captured variables are read where the compiled code holds them, and the compiler counts a binding list's names.** Each time a set or a `let` was evaluated, its bindings were decoded into a fresh Haskell list, which was then walked up to five times, once for each thing the evaluator needed from it, such as whether its frame holds its names in slots, how many slots it has and how large the set is. Each time a closure or a frame was made, its captured variables were decoded into a list of pairs. The compiler now writes at the head of each binding list how many names it binds statically and how many of its bindings have a dynamic name, which give a frame's layout, its slot count and a set's size in two reads. The bindings are folded over where the compiled code holds them, a set with no dynamic name skips the pass that binds dynamic names, and a closure's captured slots are written into its env as they are read. Results are unchanged. On `profiling/stress.nix` evaluation allocates 1.18 GB where it allocated 1.34 GB, and its mutator time falls by about 9%.
- **Library API:** `Nix.Eval.Compile.decodeBcBindings` answers `BcBindings`, a binding list's `BcBindingCounts` with its count and offset, where it answered a list of `BcBinding`; `foldBcBindings` folds over the bindings, handing a binding tag the compiler never writes to the function it is given, and `foldBcInheritedNames` folds over an `inherit (from)`'s names. `BcAttrKey` is gone: `BcNamed` holds a static name's symbol, the new `BcDynamic` holds the bytecode index a dynamic name is computed by, and `BcInheritFrom` holds `BcInheritedNames`, the names' count and offset, where it held a list. the capture info `decodeBcCaptureInfo` answers is a `BcCaptureInfo`, whose `BcCaptures` and `BcCapturesWithScopes` hold the `BcCapturedSlots` that `foldBcCapturedSlots` reads, where it was a `CaptureInfo`, and `Nix.Eval.Types.buildBcCaptureEnv` builds a closure's env from one. A binding list's bytecode starts with the two counts.
