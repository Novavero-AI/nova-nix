- **On Windows a program built on `pkgs/windows`' stage0 tools can open a file to read while another holds it open to write, as on POSIX.** Every file those programs open goes through one routine, the `open_file` in stage0-pe32's `x86/ntdll-i386.hex2`, which each link from M0 up carries and M2libc's `open` and `fopen` reach. It shared a file for reading alone, and Windows refuses an open whose sharing does not admit the access an earlier open already holds, so a file open to write could not be opened again to read, where POSIX never refuses an open because another process has the file open. GNU Mes keeps each file it writes open until it exits, and MesCC runs M1 on the assembly it has just written, which M1 could not open. `pkgs/windows` now pins stage0-pe32 at ff1c2ad, whose `open_file` shares a file for reading, writing and deletion. M0, cc_x86, M2, M1, hex2-new and kaem change with it; hex0, hex1, hex2 and catm, which carry their own copies, do not.
