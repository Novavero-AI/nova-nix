- **A build runs in a directory it creates under the store's state directory, `.nova-nix/builds`, with mode 0700 on macOS and Linux, where it ran in the system temporary directory under its first output's hash.** The build removed that path and then created it with a call that accepts a directory already there, and anyone can compute the name from the derivation, so in a world-writable `/tmp` another local user who created the directory first owned the directory the build ran in and could change its sources and scripts before the outputs were registered. The directory's default mode also let other users read what the build unpacked. The name did not depend on the store either, so two builds of one derivation into two stores at once shared one directory, and the second removed the first's tree mid-build. Upstream creates each build directory with `mkdir` and mode 0700 and never enters one that exists (`createTempDir`, file-system.cc at 2.24.9), and since 2.30.0 roots them at its state directory by default (`LocalBuildStoreConfig::getBuildDir`, local-store.cc), documenting that `build-dir` must not be world-writable. Each store's state directory holds that store's builds, and whoever can write there can already rewrite the store's database. The name is still the first output's hash, where upstream's is `nix-build-<drv name>-<n>`: the build holds that output's path lock throughout, so the name belongs to one build at a time, and a directory a killed build left there is removed before the next build of the derivation creates its own. The directory is removed when the build ends even when the builder left a read-only tree in it, as upstream's `deletePath` removes one. On Windows the directory takes the access control list it inherits from the store directory, where it was in the per-user temporary directory. A derivation with no outputs, whose build fails whatever its builder does, fails before its builder runs.
- **Library API:** `Nix.Builder.BuildConfig` has no `bcTmpDir`; a build's directory follows from `bcStoreDir`. The new module `Nix.Builder.BuildDir` names a build's directory (`buildDirFor`), creates one (`createBuildDir`) and runs a build in one (`withBuildDir`).
