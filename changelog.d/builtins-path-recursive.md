- **`builtins.path { recursive = false; }` copies the one file at the path by its bytes, to the flat fixed-output path upstream gives it, and an argument `builtins.path` does not take is refused.** `builtins.path` never read `recursive`, so `recursive = false` still copied the file as a NAR and gave the NAR's path, and it passed over any argument it did not know, so a misspelt `sha256` left the copy unpinned. Upstream's `prim_path` reads its arguments one at a time in the set's own order (primops.cc at 2.24.9): `recursive` is a Boolean choosing a NAR or a flat copy, and any argument but `path`, `name`, `filter`, `recursive` and `sha256` fails at its turn with `unsupported argument '<name>' to 'addPath'`, before the path is looked for or anything is copied. For a flat copy `addPath` hands `fetchToStore` the path with its symlinks resolved, whose flat dump reads the file's bytes and calls no filter (`addPath` in primops.cc; the flat case of `dumpPath` in file-content-address.cc), so the pin is the SHA-256 of those bytes, a pin that differs fails with `store path mismatch in (possibly filtered) path added from '<path>'` as it does for a NAR copy, and a directory fails that read with `reading from file '<path>': Is a directory` (`PosixSourceAccessor::readFile` in posix-source-accessor.cc). nova-nix now does the same. From 2.26.0 upstream names `builtins.path` in the refusal of an argument where 2.24.9 names `addPath`, and from 2.34.0 it refuses a directory through another read, in other words; nova-nix keeps 2.24.9's. The parity job compares the flat copy's path, pinned and not, and both refusals with nix-instantiate's.
