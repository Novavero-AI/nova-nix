- **`pkgs/windows` builds `gcc46-cxx`, GCC 4.6.4 with C and C++ for `i686-w64-mingw32`, compiled by `gcc46` in the seed stdenv, with libgcc and libstdc++ compiled by the compiler the same make links, so the ladder has a C++ compiler for the GCC after it.** GCC is written in C++ from 4.8 on, and nixpkgs' `minimal-bootstrap` builds its GCC 10 with the same rung, `gcc/4.6.cxx.nix`, which this follows: gcc-core's sources with GCC's g++ archive unpacked over them, and nixpkgs' flags, `-O1` for the compiler and `-O0` for the target libraries, and `install-strip`. nixpkgs gives its native compiler musl's headers and libraries; here GCC is a cross compiler, as gcc-core is, and is given MinGW-w64's headers and runtime with `--with-headers` and `--with-libs`, the pair GCC's installation guide names for a C library built outside its tree. The top-level configure copies both into GCC's own output, where gcc46 has them and where the build points the compiler it links when it compiles and links libstdc++, whose configure links its tests for a MinGW target and so needs the runtime first. libstdc++ installs beside the runtime, so `i686-w64-mingw32-g++` links a C++ program with no flag naming a directory. The build runs gcc46's driver and binutils' archiver, linker and strip under the target's names, the only names they have on `PATH`, since configure looks the host's tools up under bare names and the seed stdenv's `CC`, `AR` and `LD` are tcc's. `--disable-win32-registry` is not nixpkgs': linked against MinGW-w64's `libadvapi32.a`, a GCC for Windows looks its directories up in the registry under `HKEY_LOCAL_MACHINE\SOFTWARE\Free Software Foundation`, so a machine with a GCC installed there would change where this one looks. `--disable-shared`, as in nixpkgs, keeps libgcc and libstdc++ static, and exceptions are SJLJ, a 32-bit MinGW target's default. No program the rung installs carries the time it was built, so two builds of it at the output's own path are the same bytes. binutils' `ld` writes the time of the link into a PE image's header unless it is given `--no-insert-timestamp`, which GCC 4.6.4's link spec for MinGW never passes and the seed stdenv has no compiler wrapper to add, so `LDFLAGS` passes it to every link `gcc46` makes, of the host's programs and the build machine's. `strip`, which `install-strip` runs on each program, then writes the time over the zero `ld` wrote unless it is run with `-p`, as nixpkgs' strip hook runs it, so the install phase gives make a `STRIP` with `-p`, on make's command line since the stdenv splits `configureFlags` and `makeFlags` at spaces. `nova-nix build --check` of the rung still finds seven programs differ, the five drivers, `cc1` and `cc1plus`: the check builds at a scratch path and rewrites its hash in what the builder wrote, and each of the seven names the output and carries a sum of its own bytes that no rewrite reaches, the PE checksum `ld` and `strip` write and, in `cc1` and `cc1plus`, the MD5 GCC takes of the objects they link, two of which compile the prefix in. CI builds the rung on x64 and ARM64 Windows and has its `g++` compile and link a C++ program that prints through iostream, calls virtual functions through a base pointer, instantiates a template, uses `new` and `delete`, constructs a global and a function-local static, and throws and catches two exceptions, one after unwinding through four frames whose destructors run; the check compares what it prints and its exit status with what the C++ standard defines, and pins that it imports msvcrt.dll and kernel32.dll alone and links libsupc++'s and libgcc's SJLJ exception functions. A second check reads the time stamp in the header of every program and DLL the rung installs and compares the list with one in which each is zero.
