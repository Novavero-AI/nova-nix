- **`outputHashMode = "nar"` hashes a fixed output as a NAR, as `recursive` does, and a mode upstream does not take is refused for every derivation, with or without an `outputHash`.** `derivationStrict` read `recursive` as a NAR hash and every other value as a flat one, so `outputHashMode = "nar"` gave the flat output's path and `outputHashMode = "foo"` was accepted. Upstream's `handleHashMode` reads the mode in its pass over the attributes, whatever else the derivation holds (`derivationStrictInternal` in primops.cc): `recursive`, kept as the older name of `nar`, and `nar` hash a NAR and `flat` the output's bytes (`ContentAddressMethod::parse`, content-address.cc; `parseFileIngestionMethod`, file-content-address.cc), `text` and `git` need the `dynamic-derivations` and `git-hashing` experimental features, and any other value fails with `invalid value '<mode>' for 'outputHashMode' attribute`. nova-nix now does the same. It implements neither feature, so `text` and `git` fail as upstream fails with them off, with `experimental Nix feature 'dynamic-derivations' is disabled; add '--extra-experimental-features dynamic-derivations' to enable it` and its `git-hashing` twin. A refused mode fails at its attribute in name order, under the line `while evaluating attribute 'outputHashMode' of derivation '<name>'`, so before a missing builder or system is reported, and `builtins.tryEval` does not catch it. An empty mode, which `outputHashMode = null` coerces to unless `__ignoreNulls` leaves it out, is refused too. From 2.33.0 upstream's `text` refusal also names the derivation and its mode; nova-nix keeps 2.24.9's words. The parity job compares the paths of `nar`, `recursive` and `flat` and these refusals with nix-instantiate's.
- **Library API:** `Nix.Hash.makeFixedOutputPath` takes the method as a `FileIngestionMethod` (`FlatIngestion` or `NarIngestion`, exported from `Nix.Hash` with `fileIngestionPrefix`), where it took `"flat"` or `"recursive"` as `Text` and read every other text as flat.
