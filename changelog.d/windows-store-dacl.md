- **On Windows a store directory nova-nix creates, and its `.nova-nix` state directory, can be changed only by the user nova-nix runs as, SYSTEM and Administrators, a directory it creates on the way to the store, such as `C:\nix`, is open to them alone, and a build directory is that user's alone, where each took the permissions of the directory it was made in.** A directory made under a drive root takes the root's permissions, which let every signed-in user (Authenticated Users) modify it, so under the default `C:\nix\store` any user of the machine could change, replace or delete store paths and the store's database, rename a `C:\nix` nova-nix had made and put a store of their own in its place, and change a build's sources and outputs while it ran. nova-nix now creates each of these directories with a protected access control list, which takes nothing from its parent, in the one `CreateDirectoryW` call that makes it, so the directory never exists with its parent's permissions. A store directory and its state directory grant full control to the user, SYSTEM and Administrators and read and execute to Users, the rights, inheritance and principals install-nova-nix sets on `C:\nix`; a parent directory nova-nix creates on the way to the store grants full control to the user, SYSTEM and Administrators and nothing to other users; a build directory grants full control to the user alone, as its mode 0700 does on macOS and Linux. Each grant is inherited by what is made below, so store paths and a build's tree are covered too. A directory that already exists keeps the permissions it has, so a store that took a drive root's permissions before this release still lets every signed-in user modify it; install-nova-nix refuses such a store in `C:\nix` and asks for `C:\nix` to be moved aside. install-nova-nix accepts a `C:\nix` this release creates, since it grants nothing to an account the installer does not trust, and gives it the installer's own permissions, which add read and execute for Users. A store created inside a private folder, such as a `--store` under the user's profile, now grants Users read and execute, as a store's permissions do wherever it is, where it took the folder's own list before, which under the profile grants other users nothing. Upstream's local store creates its directories with `std::filesystem::create_directories` on every platform and sets no access control list on Windows (`createDirs`, file-system.cc, and the `LocalStore` constructor, local-store.cc, at 2.24.9). macOS and Linux are unchanged.
- **Library API:** the new module `Nix.Store.Access` creates a directory open to whom a `DirAccess` says (`StoreAccess`, `ParentAccess` or `OwnerAccess`, with `createDirectoryWith`) and a store's state directory with the store directory it is in and any missing parent (`createStateDirectory`), and gives the SDDL a directory is created with on Windows (`accessSddl`), for a `Sid` that `sidFromText` makes only from a SID's string form, `S-1-I-S...`, so no trustee can carry another entry into the DACL. `Nix.Store.DB` exports `createStoreDirectories`, which `openStore` and `openStoreDB` create a store's directories with.
