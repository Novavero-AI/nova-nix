- **Only a fixed-output derivation's builder sees the variables its `impureEnvVars` lists, as upstream decides by the derivation's type: a floating content-addressed output, an impure one, and a fixed output beside others or not named `out` no longer pass them.** The variables reached any build with an output that names a hash algorithm, which a floating content-addressed output does too. Upstream passes them to a derivation whose type is not sandboxed (local-derivation-goal.cc:1176-1189 at 2.24.9), and the type is fixed-output only for one output, `out`, with the hash that fixes it (derivations.cc:734-748). A floating output, which names an algorithm and no hash, is sandboxed (derivations.cc:751-759), and a fixed output beside others or named otherwise makes a derivation upstream refuses (derivations.cc:740-744 and 777). Upstream also passes them to an impure derivation, which takes the experimental `impure-derivations` feature that nova-nix does not implement. nova-nix makes no floating or impure derivation and reads none upstream writes, since upstream writes such an output with no path (derivations.cc:604-619), so one reaches the builder only from the library or a `.drv` written by hand. The rule is the one `nova-nix trust` uses to find a closure's fixed-output derivations.
- **Library API:** `Nix.Derivation` exports `fixedOutput :: Derivation -> Maybe DerivationOutput`, the one output of a fixed-output derivation.
