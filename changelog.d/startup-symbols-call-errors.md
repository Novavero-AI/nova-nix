- **The names upstream's evaluator interns as it starts are interned first, in its order, so `({ }: null) { zzz = 1; x = 2; }` names `x` as the unexpected argument, as upstream does, where it named `zzz`.** A set holds its attributes in symbol order, and a symbol's place is the order its name was interned in, so that order decides which failure wins wherever a walk over a set stops at the first. Upstream's `EvalState` interns its static symbols as it is constructed (the `EvalState` constructor in eval.cc at 2.24.9), then every name `createBaseEnv` installs, each followed by that name less a `__` prefix (`EvalState::createBaseEnv` in primops.cc, `EvalState::addConstant` and `EvalState::addPrimOp` in eval.cc), then the names of its `derivation` wrapper, which it parses last (the end of `EvalState::createBaseEnv` in primops.cc, primops/derivation.nix), before it parses a program; `x` is one of the wrapper's. nova-nix interned its builtins' names in name order when a program first used them, after the program's own. The order of the primops is the order their files' static initializers run in: link order at 2.24.9, and the same order at 2.35.0, which compiles the files as one unity build. The release builds of 2.27.0 through 2.34 link under GCC's link-time optimization, which runs the initializers in reverse, so there `getContext` comes before `toString`; nova-nix follows 2.24.9. The order still differs under `pure-eval`, where upstream leaves out `currentTime` and `currentSystem` and their `__` spellings, and with an experimental feature on, whose primops upstream then installs. (#378)
- **A call to a set pattern checks for a missing argument before an unexpected one and words both as upstream does, naming the function, and a select of a missing attribute and `abort` word their failures as upstream does: `({ a }: a) { b = 1; }` fails with `function 'anonymous lambda' called without required argument 'a'`, `let f = { }: 1; in f { a = 1; }` with `function 'f' called with unexpected argument 'a'`, `{ a = 1; }.b` with `attribute 'b' missing` and `abort "boom"` with `evaluation aborted with the following error message: 'boom'`.** An argument's or attribute's name prints as upstream prints a symbol, bare when the lexer reads it as an identifier and otherwise as a string literal (`({ }: null) { "a b" = 1; }` names `'"a b"'`, the empty name `'""'`), as upstream writes a symbol through `printIdentifier` (the `operator<<` for `SymbolStr` in nixexpr.cc); the function's name prints as its binding spells it, as upstream passes it as a plain string. nova-nix named the unexpected argument first, as `unexpected attribute 'b' in function argument`, listed every missing argument and the keys given, named a missing attribute by its whole path with the set's keys, and printed `abort`'s message alone. Upstream's `callFunction` checks each formal in symbol order, which its parser sorts formals into, and stops at the first that has neither an argument nor a default, then names the first attribute in symbol order that no formal names (eval.cc, and `ParserState::validateFormals` in parser-state.hh); both carry the line `from call site`, and an argument that is not a set fails as `expected a set but found ...` with that line and `while evaluating the value passed for the lambda argument` (`EvalState::callFunction` in eval.cc). A function takes the name of the attribute a set or `let` binds it to, as does a function that is its body (`ParserState::addAttr` in parser-state.hh, `ExprLambda::setName` in nixexpr.cc), and is otherwise `anonymous lambda`. A select reads each name before it forces the value it selects from, fails at a value that is not a set as `expected a set but found ...` with `while selecting an attribute`, and names the one name a set lacks (`ExprSelect::eval` in eval.cc); `abort` words its message (`primop_abort` in primops.cc). The wording and the printing of names are the same at 2.34.9 and 2.35.4. Neither the position each of these errors carries upstream nor the `Did you mean` suggestions it prints with an unexpected argument or a missing attribute are printed, and the `from call site` line is not added where forcing the argument itself fails, nor `while evaluating the attribute` to a failure under a select. The traces are upstream's with `show-trace` off, its default, which adds no lines for the calls a failure in a function's body passes through (`EvalState::callFunction` in eval.cc). Upstream also names a function under a dynamic key, with the name the key evaluates to, each time it evaluates the set (`ExprAttrs::eval` in eval.cc); such a function is `anonymous lambda` here. - **Library API:** `Nix.Eval.EvalFormals.EFSet` and `EFNamedSet` take the function's `LambdaName` (`AnonymousLambda`, or `NamedLambda` holding the name's `Symbol`) as their first field, which `lambdaNameText`, `lambdaNameSymbol` and `lambdaNameFromSymbol` read. `Nix.Eval.StartupSymbols.startupSymbols` lists the names an evaluation session interns first, and `Nix.Eval.Symbol.invalidSymbolId` is exported. `Nix.Eval.CLambda.clambdaNew` takes the function's name symbol after the binding's and refuses a formals type or count its closure cannot hold, `clambdaLambdaNameSym` reads the name, and `clambdaShape`, `clambdaShapeFormalsType`, `clambdaShapeAllowExtra` and `clambdaShapeFormalCount` pack and unpack the one word a closure keeps its formals type, ellipsis flag and formal count in. `Nix.Eval.Print.printSymbol` prints a name as upstream writes a symbol into a message. `Nix.Eval.runPureEval` reports an abort with its message alone, as `Nix.Eval.IO.runEvalIO` does, where it prefixed `evaluation aborted: `.
