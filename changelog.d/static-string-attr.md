- **A key written `${"a"}`, a double-quoted string with no interpolation between `${` and `}`, or a URI there, is the name it spells, as upstream's parser makes it, so `let ${"a"} = 1; in a` is `1` and `let a = 1; in { inherit ${"a"}; }` inherits `a`, where both were syntax errors.** Upstream's `attrpath` and `attrs` rules make a key a name when its expression is a plain string, an `ExprString`, and dynamic only otherwise (parser.y); a double-quoted string with no interpolation is one, and so is a URI (the `URI` case of `expr_simple` and the `string_parts` rule, parser.y), parenthesized or not. nova-nix made a key a name only when it was written as a double-quoted string, so a `${"a"}` key stayed dynamic: refused in a `let` and in an `inherit`, outside a `rec` set's scope, so `rec { ${"a"} = 1; b = a; }` failed as an undefined variable, and apart from the same name written bare, so `{ ${"a"}.b = 1; a.c = 2; }` failed when evaluated where upstream merges the two paths, and `{ b = 1; ${"b"} = 2; }` failed when evaluated where upstream refuses it as it parses. A dynamic key in an `inherit`, `inherit ${x};` or `inherit "${x}";`, fails with upstream's `dynamic attributes not allowed in inherit` at the key's start. A `${ }` key whose string is not UTF-8 is a syntax error at the key, as a double-quoted one already was, where it failed only when its set was evaluated; upstream makes a name of any bytes. A key whose expression is an indented string stays dynamic: upstream makes it a name when `stripIndentation` (parser-state.hh) leaves it a single piece, and this parser holds an indented string as its unstripped pieces until it is evaluated.
