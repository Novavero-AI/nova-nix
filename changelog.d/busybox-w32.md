- **`pkgs/windows` builds busybox-w32 FRP-6354-g5f09fb446 with `tinycc-native`, as upstream's `mingw32_defconfig` build, in one `i686-windows` `kaem.runCommand` script with no shell: the shell and tools the native rungs run configure under.** Upstream compiles busybox-w32 against MinGW-w64's headers and links MinGW-w64's runtime; this compiles it against TinyCC's own headers, with a compatibility layer of the MinGW-w64 declarations busybox-w32 reads and TinyCC's headers lack, and links five mingw-w64-crt v14.0.0 sources for the functions msvcrt.dll lacks. The headers upstream's build generates are written as it writes them: kconfig's `conf`, `applet_tables` and `usage` are compiled and run, and the shell scripts `scripts/gen_build_files.sh` and `applets/usage_compressed` are C programs in the package. Three settings differ from `mingw32_defconfig`, each for something this toolchain lacks: usage text is stored unpacked, since packing it takes bzip2 at build time; the executable carries no version information, manifest or icon, which take a resource compiler; and busybox does not expand wildcards in its own arguments, which MinGW-w64's startup code does and TinyCC's does not, so `busybox --help` reports noglob. Seven edits to the source, as well as those to the configuration, are each checked against the edited file's SHA-256, since `replace` leaves a file unchanged when its match is missing. Three are for what TinyCC does not compile as GCC does: a string literal in parentheses as an array initializer, `bswapl`, which TinyCC's assembler knows as `bswap`, and a call, in code no configuration without Unicode reaches, to a function such a configuration does not define, which TinyCC compiles where GCC drops it. Three supply what upstream's toolchain would: `dirname`, which busybox-w32 carries for newer MinGW-w64 runtimes; `ffs`, a GCC builtin; and the binary file mode MinGW-w64's startup code sets. The seventh keeps `printf`'s exit status 0 for an argument of 128 bytes or more: busybox-w32 formats each directive through msvcrt.dll's `_vsnprintf`, which sets `errno` to `ERANGE` when the output fills or overflows the 128-byte buffer libbb's `vasprintf` tries first, and `printf` takes the `errno` its directives leave for a conversion error, so it wrote such an argument whole and exited 1. GMP 6.2.1's `configure`, whose last command writes a summary that long, failed for it once it had configured. `time_t` is 32 bits, as TinyCC's headers define it for i386; the stack reserve is upstream's 2 MiB; and `busybox.exe` needs the msvcrt.dll of Windows Vista or later, where upstream's i686 build takes `_chsize_s`, `_set_fmode`, `getenv_s` and `strnlen` from MinGW-w64's runtime on older ones. CI builds it on x64 and ARM64, checks `busybox --version`, and has busybox's sh run a script through `sh`, `sed`, `grep`, `awk`, `expr`, `tr`, `cat`, `mkdir`, `rm`, `cp`, `mv`, `test` and `printf`, one of a 200-byte argument among them, checking each line it writes.
