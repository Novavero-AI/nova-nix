- **`nova-nix profile add`, `profile remove` and `profile list` keep a profile of generations in upstream's layout, each generation a root the garbage collector keeps, so a package added to the default profile puts its programs under `~/.nix-profile/bin`.** They are `nix profile`'s commands of those names at 2.35.4. A profile is a link to one of its generations, `PROFILE-1-link`, `PROFILE-2-link` and on beside it, and each generation is a store path named `profile` holding the packages' files linked into one tree, as `builtin:buildenv` links them, and a `manifest.json`, version 3, written byte for byte as upstream writes it, added as a NAR-hashed path whose references are every package's paths, as upstream adds it, so its store path is computed the way upstream computes one. A new generation is one past the highest, unless the highest already names the path, and each is linked as `build` links its output, so it is an indirect root `store gc` follows and `store gc --print-roots` lists. The default profile is upstream's for a user who is not root: `profiles/profile` under `$NIX_STATE_HOME`, else `$XDG_STATE_HOME/nix`, else `~/.local/state/nix`, and on Windows `nix\state` under the Local AppData folder, linked from `~/.nix-profile`, or from `profile` in the state directory when nix.conf's `use-xdg-base-directories` is on; every profile command makes the directory and the link when they are missing, as upstream's do, and `--profile` names another profile. `profile add` takes what `build` takes and builds the outputs upstream installs (the one `outputSpecified` selects, else those `meta.outputsToInstall` names, else every output), or a store path, or a link into the store such as `./result`; names the package after its paths' names without their versions, with `-1`, `-2` and on appended to a name already taken; gives it `--priority`, 5 by default; and fails a file two packages of one priority hold with upstream's message, its hints naming nova-nix's commands. `profile remove` takes a name, a store path, `--regex` (a POSIX extended regular expression matching the whole name, ignoring case) or `--all`, prints upstream's lines, and refuses a line that selects nothing, or `--all` beside another selector, as usage errors, reported as nova-nix reports its other usage errors. It refuses a number as upstream refuses an index, in words of its own, `does not support indices`: upstream's say it no longer supports them, which describes upstream's history, and nova-nix never took one. `profile list` prints upstream's lines, a name in bold and `(inactive)` in red where 2.36.0 styles stdout, on a terminal whose `TERM` is not `dumb` or wherever `CLICOLOR_FORCE` or `FORCE_COLOR` is set, and never under `NO_COLOR` or `NOCOLOR` (a name holding an escape sequence of its own keeps it there, where 2.36.0 takes every escape out of the line), or with `--json` the manifest, indented when stdout is a terminal unless `--pretty` or `--no-pretty`, upstream's flags, say otherwise. Manifests of versions 1 to 3 are read. Where nova-nix differs from upstream: a change reads the profile's link, makes the new generation's store path, then takes the profile's lock, `PROFILE.lock`, and starts again with upstream's `changed while we were busy; restarting` if the link moved meanwhile, as `nix-env` does; upstream's `nix profile` takes no lock, so two changes at once there can both start from one manifest and the later drop what the earlier added. The lock file stays once released, as every nova-nix lock file does. Every profile command refuses a profile whose current generation is outside the store it uses, the store and the profile compared with their links resolved, and names `--store` and `--profile`, since a user with upstream Nix installed shares `~/.nix-profile` with it while nova-nix's store is elsewhere, and a generation read against the wrong store names paths that store does not hold; upstream has one store, and its `profile list` lists any profile. And a profile only `nix-env`'s `manifest.nix` describes is refused rather than read, a version 1 or 2 manifest's flake element, which upstream names from its URL, is refused, a flake element of version 3 keeps the fields it was read with where upstream parses and renders them again, and `--priority` takes an int with no binary unit suffix, where upstream takes a suffix and narrows a 64-bit value. Root's profile is where any user's is, where upstream keeps root's under its state directory, of which nova-nix has none apart from the store. On Windows every link is a symlink, which needs Developer Mode or an elevated shell, and a switch removes the profile's link and makes it again, since a rename cannot replace a directory link there.
- **Library API:** `Nix.Profile.Manifest` reads and writes `manifest.json` and selects its elements as `profile remove` does, and `Nix.Profile.Generation` finds where profiles are from a `ProfileEnvironment`, resolves the default profile, names and lists generations, and changes a profile through `updateProfile`. `Nix.Store.addSourceTree`, and the `StoreOps` field `soAddSourceTree`, add a tree given as its NAR as the content-addressed path its name and references make, so a `StoreOps` built by hand gains that field. `Nix.Config.NixConfig` gains `ncUseXdgBaseDirectories`, and `Nix.HostPath` exports `hostPathBytes`, the inverse of `hostPathFromBytes`.
