- **On Linux and macOS an unsandboxed builder that runs as the user nova-nix runs as starts and ends as upstream's does: in a session of its own, reading `/dev/null`, with every other descriptor closed and no core dumps, and with every process left in its process group sent SIGKILL once its log ends, or when the build is interrupted.** It started through the process library, which left it nova-nix's controlling terminal, its core limit and its descriptors, and an interrupt sent SIGTERM to the builder alone, so what the builder had started ran on after the build. Upstream's child makes a session of its own, reroutes standard input to `/dev/null` and sets the soft core limit to 0, and upstream takes the builder's status by killing its process group, so a builder that closes its log but keeps running now fails on signal 9, as upstream's does; a build user's builder ends the same way. The builder is executed by its path, with no search of `PATH`, as upstream executes it.
