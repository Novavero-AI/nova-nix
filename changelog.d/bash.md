- **`pkgs/windows` builds GNU Bash 5.3 with GNU's twenty official patches, as `bash`, with the package set's stdenv, for x86_64 Windows on msvcrt alone, with no Cygwin or MSYS2 runtime, and CI's new Bash stage, after Stdenv on its handoff, checks it on x64 and ARM64.** nixpkgs' generic stdenv runs `setup.sh` under bash and setup.sh needs bash 5, so a from-source Windows stdenv for nixpkgs needs a bash built on the ladder. Windows has no fork, and bash forks for every child, so the port, in `pkgs/windows/by-name/ba/bash`, starts a program as a new process where bash would fork and exec one: the shell makes the program's redirections its own while it starts it, with CreateProcess, giving it exactly the descriptors a forked child would keep, close-on-exec and append mode included, through the table msvcrt passes a child and a list of the handles it inherits, then undoes them. A `#!` script runs its interpreter, which bash starts itself, as Windows reads no `#!` line (configure's check passes only because busybox-w32's `sh` reads it, so bash is told the system does not), a script with no `#!` line runs in a new bash, and `exec` and `bash -c` stand in for the program they would exec by waiting for it and exiting with its status. Subshells, command substitution, pipelines and background jobs, which need a copy of the shell, fail with `fork: Function not implemented` for now. A script's `PATH` keeps what it writes; the command search and a program's environment split it at `;` and at a `:` that does not end a drive letter, as busybox-w32 does, so a `PATH` of `C:\...` directories joined with `:` works, and a program finds it joined with `;`; in each directory the search takes `NAME.exe` where `NAME` is no program. `/dev/null`, `/dev/tty` and `/dev/fd/N` open as Windows names them, and a program's exit status reads back as POSIX's, an access violation as SIGSEGV. bash's malloc casts pointers to `long`, which is 32 bits on Windows, and now casts them to `intptr_t`; `builtins/psize.c` stops counting at a failed write where no SIGPIPE comes; and four of bash's files that assumed `st_blocks`, `TIOCGWINSZ`, networking or a header another one includes now build without them. GNU publishes the patches as context diffs, which busybox's `patch` does not read, so each is rewritten as the unified diff it is before it applies; the result is the tree GNU's `patch -p0` makes of them. The checks have bash run, as a build's builder, a script of functions, indexed and associative arrays, `local -n` and `shopt -s inherit_errexit`, and a program and two `#!` scripts, one whose interpreter is bash and one whose interpreter is another program, found on such a `PATH`, with their arguments, redirections and exit statuses.
