- **A store path refused for its name is refused in upstream's words, naming the path it would have had.** `builtins.toFile "a b" "x"` fails with `path 'dm85kbl5cy82j2dzvy1874s14y3salv3-a b' is not a valid store path: name 'a b' contains illegal character ' '`, as on Nix 2.24.9, where it gave a message of nova-nix's own behind a `builtins.toFile:` prefix. Upstream refuses the name where it builds the path, once the hash exists (the `StorePath` constructor in `path.cc` at 2.24.9), and names the builtin only in its trace, so the same text now comes from `builtins.path`, `builtins.filterSource`, a path copied to the store by interpolation, and a derivation whose name fits but whose `.drv` name or `name-output` does not. A source copy hashes its tree before refusing its name, as upstream's does, since the hash part is the tree's. A `builtins.path` with `sha256` is refused under the pinned hash before the tree is read, as upstream's `addPath` builds the pinned path first. Of two outputs past the length cap, the one refused is the first by name, as upstream builds the paths over its sorted output set.
- **Library API:** `Nix.Hash`'s `makeStorePath`, `makeTextPath`, `makeFixedOutputPath` and `makeOutputPath` return `Either BadStorePath StorePath`, where the new `Nix.Store.Path.BadStorePath` holds the hash part the path would have had and its `StorePathNameError`, and `badStorePathText` renders it. `Nix.Eval.Types.storePathOrThrow` takes no context argument.
