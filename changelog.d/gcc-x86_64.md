- **`pkgs/windows` builds `gcc-x86_64`, GCC 16.2.0 with C and C++ for `x86_64-w64-mingw32`, compiled by `gcc-latest` in the seed stdenv against MinGW-w64 v14.0.0's headers and the x86_64 runtime: the ladder's first compiler that writes 64-bit programs.** It finishes the cross toolchain MinGW-w64's build guide builds, as nixpkgs' `pkgsCross.mingwW64` builds its GCC. The build is `gcc-latest`'s, one cross compiler build given its target's headers and runtime with `--with-headers` and `--with-libs`, so libgcc and libstdc++ are built against them by the same make and the installed driver finds all of them with no flag. The flags are those of nixpkgs' cross compiler, where `gcc-latest`'s are `minimal-bootstrap`'s: the compiler and its target libraries are `-O2`, configure's own optimization, without the `-g` nixpkgs strips after its install, and the build ID, gcov, the analyzer and libstdc++'s visibility and ABI are configure's defaults. nixpkgs gives libstdc++ the mcf thread model from mcfgthreads, which the ladder does not build; the model here is win32, the target's own on the Windows API alone and nixpkgs' choice for a MinGW target with no thread library, under which libstdc++ has `std::thread` because the headers name Windows 10. Exceptions are SEH, the x86_64 target's. Where nixpkgs' choices need what the ladder does not have, `gcc-latest`'s are kept: GMP, MPFR and MPC in the tree and no ISL, the tree's zlib, no NLS, static libgcc and libstdc++, so a program imports no DLL of GCC's, no LTO or plugins, and the target libraries other than libgcc and libstdc++ off. nixpkgs' patch for a Windows target serves a libstdc++ built without its C library, and this one is hosted. CI builds the rung on x64 and ARM64 Windows in a stage of its own, GCC 16 x86_64, which starts from the store x86_64 now hands on. Its `gcc` compiles and links a C23 program that prints the x86_64 Windows sizes of a pointer, a long, a long long and a long double, divides 128-bit integers through libgcc and multiplies `_BitInt(256)` values through it, and its `g++` the C++20 program `gcc-latest`'s check links, threads and exceptions included, which here unwind through SEH. Each check compares what its program prints and its exit status with what the standards and the ABI define, and pins the DLLs it imports, the libgcc, libsupc++ and libstdc++ functions it links, that it has no build ID and no debugging section, and the machine and optional header magic of its PE header, an x86_64 PE32+ image. A third check reads the time stamp in the header of every program the rung installs and compares the list with one in which each is zero.
