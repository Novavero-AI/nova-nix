- **`nova-nix trust` reports what a derivation's closure relies on: its fixed-output derivations, those a build runs as builders and those holding prebuilt code, each file named with its kind, those not fully read, and the builders and sources the closure takes from outside itself.** Every closure bottoms out in fixed-output derivations, whose bytes a hash pins whatever fetches or builds them, but which of them are readable source and which are prebuilt code was not visible anywhere. The classification rests on facts, never on a name or a URL's suffix, which this repository's own recipes disprove: stage0-pe32's source archive also holds the `hex0-seed.exe` its chain starts from, and the MSYS2 packages the Windows stdenv starts from are `.pkg.tar.zst` archives of prebuilt programs and libraries. One fact is in the graph: a fixed-output derivation runs as a builder when a derivation's builder is inside its output, or inside the tree a builtin such as `builtin:unpack`, which runs nothing from the closure, makes from it and any others. Each entry says whether a builtin fetched it or the closure built it, and names any other fixed-output derivation pinned to the same hash, as stage0-pe32's `hex0.exe`, built by running the seed, is pinned to the seed's. The other fact is in the bytes: prebuilt code found by its header, a PE image, an ELF file (an image or an object), a Mach-O file, a COFF object in the plain or the bigobj form, or an ar archive such as a static library, whose members are not read. The scan looks in a fetched file, in each file of a fetched tree, and in each file of a tar archive, plain or compressed with gzip, bzip2, xz or zstd, the format told by the bytes. An archive inside another is not opened, and a file in another archive format the scan knows, such as zip or an MSI installer, is reported as not read rather than as holding no prebuilt code. A fixed-output derivation that a builtin fetches with no input of its own is fetched first, or substituted, so that its bytes can be read; any other is read only when the store already holds it, since making it would run its builder. nixpkgs' `meta.sourceProvenance` is not read: it is a maintainer's claim, made during evaluation and absent from the `.drv`. The report says what the closure relies on, not whether any of it is safe.
- **Library API:** the new module `Nix.Trust` classifies the fixed-output derivations of a `DepGraph` from the graph and from content facts it is given, and renders the report; `Nix.Trust.Scan` reads a fetched output's bytes for those facts.
