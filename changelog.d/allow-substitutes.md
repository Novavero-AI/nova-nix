- **A build no longer substitutes the outputs of a derivation whose `allowSubstitutes` attribute is false: it builds them, as upstream does, unless `always-allow-substitutes` is on in nix.conf or `NIX_CONFIG`.** nova-nix did not read the attribute, so such a derivation came from a cache whenever one held its outputs. nixpkgs sets it on the builds that cost less to run than to download, `runCommandLocal` and `writeTextFile` among them. Upstream reads the attribute in `ParsedDerivation::substitutesAllowed` (parsed-derivations.cc at 2.24.9) and starts no substitution for a derivation that forbids it (`DerivationGoal::haveDerivation`), going on to its inputs, which are substituted or built as any other derivation's are. A derivation without the attribute may be substituted. In a derivation's environment only `1` allows it, which is how evaluation writes `true`; with structured attributes it is a JSON Boolean, and any other value there stops the build with upstream's message, `attribute 'allowSubstitutes' of derivation '<hash>-<name>.drv' must be a Boolean`. The rule covers what a derivation's own goal does: a path that another substituted output references still comes from the cache, since upstream's `PathSubstitutionGoal` never reads the attribute. `always-allow-substitutes` lets every derivation be substituted and leaves the attribute unread, as upstream's setting does. Structured attributes that are not JSON now stop the build before the derivation's outputs are looked at, with `cannot process __json attribute of '<hash>-<name>.drv'`, as upstream's `ParsedDerivation` constructor stops it; nova-nix raised that only when it came to build the derivation, and named it by its `name`. Upstream also derives the flags `--always-allow-substitutes` and `--no-always-allow-substitutes` from the setting, and reads the attribute when it estimates what a build will fetch (`Store::queryMissing`); nova-nix has neither the flags nor the estimate. (#412)
- **Library API:** `Nix.Realise.realise` takes a `RealiseSettings`, holding `rsFallback` and `rsSubstitutes`, where it took a `Fallback`. `RealiseFailure` gains `InvalidDerivation`, `BuildConfig` gains `bcSubstitutes` and `NixConfig` gains `ncAlwaysAllowSubstitutes`, so a record built without a default needs the new field. `Nix.Realise` exports `derivationAttrs` and `substitutesAllowed` with their types, and `storePathBasename` is defined in `Nix.Store.Path`, which exports it as `Nix.Push` still does.
