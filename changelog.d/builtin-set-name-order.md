- **`builtins.listToAttrs`, `builtins.groupBy` and `builtins.fromJSON` intern each name of the set they build as they meet it, as upstream's do, so `({ }: null) (builtins.listToAttrs [ { name = "zb"; value = 1; } { name = "za"; value = 2; } ])` names `zb` as the unexpected argument, as upstream does, where it named `za`.** A set holds its attributes in the order their names were interned (`Bindings`, attr-set.hh at 2.24.9), and that order decides which of two failures a walk over a set stops at first: the unexpected argument a call names and the pair `==` forces first. Upstream's `prim_listToAttrs` interns an element's name as it reads it, before the next element (primops.cc:2896), `prim_groupBy` interns the name its function returns before it calls the function on the next element (primops.cc:3713), and `builtins.fromJSON` interns a member's name as the parser reaches it, before the member's value (json-to-value.cc:50-52), so a name the document repeats keeps the place its first occurrence gave it and takes its last value. nova-nix collected each builtin's names by name and interned the ones new to its table in name order as it built the set. Each now interns a name where upstream's does, and `builtins.fromJSON` reads an object's members in document order, so `({ }: null) (builtins.fromJSON "{\"zb\": 1, \"za\": 2}")` names `zb`, and `builtins.listToAttrs [ { name = "zb"; value = throw "b"; } { name = "za"; value = 1; } ] == builtins.listToAttrs [ { name = "zb"; value = 1; } { name = "za"; value = throw "a"; } ]` fails with `b`, as under upstream.
- **Library API:** `Nix.Eval.Types` exports `attrSetFromSymbols` and `attrSetFromSymbolEntries`, which build a set from names already interned. `Nix.Json` exports `parseJsonInto`, which hands each value it reads to a `JsonBuilder`, an object's members in document order with a repeated name each time it appears, as nlohmann's SAX interface does.
