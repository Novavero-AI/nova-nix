- **`--keep-failed`, or `-K`, and the `keep-failed` setting keep the directory of a build that fails and name it, and keep the rebuild of an output that `build --check` finds different as `PATH.check`, as upstream's do.** Without them a failed build's directory and a differing rebuild are removed, as before, so neither what made a build fail nor what a check found different could be read. The flags are `nix-build`'s, and `--keep-failed` is also `nix build`'s; nova-nix takes both on every command that builds (`eval`, `build`, `develop`, `print-dev-env` and `profile add`), and like `--fallback` a flag only turns the setting on. A build that does not succeed, one that stops short of registering its outputs, is interrupted, or is a check that finds an output different, keeps its directory under the store's `.nova-nix/builds` and prints upstream's `note: keeping build directory "DIR"` on stderr before its failure is reported. `DIR` is the directory the builder worked in: for a build in the Linux sandbox, the `build` directory inside the build directory, which the builder saw at `sandbox-build-dir`, as upstream names it. The sandbox's chroot is removed whatever the setting says, as upstream's is. A build whose builder is a builtin keeps nothing, as upstream's does, since a builtin's directory may hold privileged files. A build the sandbox refuses is now refused before its directory is made, as upstream refuses one before it makes one. A check that finds an output different moves that output's rebuild, as it was compared, its scratch hashes rewritten and its metadata canonical, to the output's path with `.check` after it, replacing whatever was there, registers nothing, and fails with upstream's `derivation '<drv>' may not be deterministic: output "<path>" differs from "<path>.check"`; only the first output that differs is kept, since the check stops there, as upstream's does. A collection removes a `.check`, which no row registers, even beside a live path, as upstream's removes one unless its path is in use at the time; a kept build directory is under the state directory, which a collection never reads, as upstream's build directories are outside its store. Without `keep-failed` the check's message is upstream's `output "<path>" differs`, its path now in double quotes as upstream quotes it, where nova-nix used single quotes. Three things differ from upstream. A kept directory keeps mode 0700, where upstream opens it with 0755 because its builder ran as a build user whose files the user who asked could not otherwise read; here the builder ran as that user. A kept directory stays until the derivation is next built, which removes it as it removes whatever an earlier build left at the name, where upstream's stays until it is removed by hand, since no later build takes its name: the name is the derivation's first output's, so that a rebuild sees the paths the first build saw, and keeping a directory must not move the next check of that derivation somewhere else. And on Windows a failed build's directory is kept too, where upstream's Windows builds remove theirs whatever the setting says.
- **Library API:** `Nix.Builder.BuildConfig` has a new strict field, `bcFailedBuilds :: FailedBuilds`, which `defaultBuildConfig` sets to `RemoveFailed`. `Nix.Builder.BuildDir` exports `FailedBuilds`, `WorkDir`, `workDirIn` and `BuildEnding`, and its `withBuildDir` takes, after the first output, where in the directory the builder works, what a failed build keeps, and how the build's result says it ended. `Nix.Realise`'s `OutputDiffers` and `NotDeterministic` carry a new `DifferingRebuild`, `RebuildKept` or `RebuildDiscarded`, and `checkedOutputPath` names where a kept rebuild is. `Nix.Config.NixConfig` has a new strict field, `ncKeepFailed`. `Nix.Store` exports `moveOutput`, the move a build makes into the store.
