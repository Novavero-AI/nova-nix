- **`builtins.listToAttrs` reads an element's `value` only for the first element of its name, so `builtins.listToAttrs [ { name = "a"; value = 1; } { name = "a"; } ]` is `{ a = 1; }`, where it failed with `builtins.listToAttrs: element missing 'value'`.** Upstream's `prim_listToAttrs` (primops.cc at 2.24.9) forces each element to a set and reads its `name`, first to last, and looks `value` up only for a name it has not seen, since the first element of a name gives its attribute; nova-nix looked `value` up on every element before keeping the first of each name. Its failures are now upstream's, each with the line of context upstream gives it: an element without `name`, or the first element of a name without `value`, is `getAttr`'s `attribute 'name' missing` or `attribute 'value' missing` with the line `in a {name=...; value=...;} pair` (primops.cc at 2.24.9, `EvalState::getAttr` in eval.cc at 2.36.0), an element that is not a set is `expected a set but found ...`, and an argument that is not a list `expected a list but found ...`, where each had a message of its own.
