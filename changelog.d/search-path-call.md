- **The parser makes `<name>` the call `__findFile __nixPath "name"`, as upstream's parser does, so neither the expression tree nor the bytecode has a node of its own for a search path.** The resolver turned that node into the same call before anything evaluated it, so the bytecode's search-path operation ran for no parsed source, and a node a library caller compiled by hand looked `builtins.findFile` up where the parser's call uses the `__findFile` in scope.
- **Library API:** `Nix.Expr.Types.Expr` loses `ESearchPath` and `Nix.Eval.CBytecode` loses `OpSearchPath`. `Nix.Parser` no longer exports `parseNixFile`, which nothing called: a caller reads the file and passes its bytes to `parseNix`.
