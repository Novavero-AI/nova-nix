- **`pkgs/windows` builds MinGW-w64's runtime with GCC 4.6.4, and `gcc46`, that compiler with libgcc and the runtime in one prefix, so the ladder now has a compiler that turns a C source into a Windows program that runs.** `mingw-w64-crt` compiles release v8.0.3's runtime, from the archive `mingw-w64-headers` already fetches, with `gcc-core` and binutils' `as`, `ar`, `ranlib` and `dlltool`, for i686 against msvcrt.dll: `crt2.o` and the other start files, `libmingw32.a`, `libmingwex.a`, `libmoldname.a`, `libm.a` and an import library for each DLL. It configures the runtime's own directory from a build directory beside it, as MinGW-w64's build guide does, with `--host=i686-w64-mingw32` so that configure looks the tools up under the target's name, and with the stdenv's `CC`, `AR` and `C_INCLUDE_PATH` unset: configure takes the compiler and archiver the environment names, which in the seed stdenv are tcc's, and GCC reads `C_INCLUDE_PATH` too, which names TinyCC's headers and comes before GCC's own and MinGW-w64's in its search. `--enable-lib32` and `--disable-lib64` are nixpkgs' flags for an i686 host: left to itself, configure decides each by compiling a test, and a compiler that fails the test for another reason would leave a runtime with no libraries and a build that passes. `CFLAGS=-O2` is configure's default for GCC without the `-g` whose debugging information would name the build directory and the store paths the compiler read, and make builds with `$NIX_BUILD_CORES` jobs, as nixpkgs' does, and installs with one, since two of the runtime's install rules write `lib32/libntoskrnl.a`. `gcc46` compiles nothing: it copies `gcc-core`'s output and puts the runtime's in its `i686-w64-mingw32` directory, where the guide installs the runtime in the GCC core's prefix and where GCC's own build looks for its target's libraries. GCC's driver takes its directories relative to the one it runs from when that is not the one it was configured for, so the copy's driver finds `crt2.o`, libgcc and the libraries every link names with no flag, and GCC is not compiled a second time. CI builds both on x64 and ARM64 Windows. One check pins every file the runtime installs and the symbols of `crt2.o`, which defines `__CTOR_LIST__` itself when configure's one link test fails, so that a test failing on Windows for another reason shows instead of changing the runtime quietly. The other has `gcc46` compile and link a program with no flag naming a directory and run it: it prints through msvcrt.dll's `puts` and `printf`, divides 64-bit integers through libgcc's `__divdi3` and `__moddi3`, and imports from msvcrt.dll and kernel32.dll alone.
