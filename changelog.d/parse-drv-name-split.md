- **`builtins.parseDrvName` splits a name at the first dash that something other than an ASCII letter follows, as upstream does: `foo-.1` is `foo` and `.1`, `foo--1` is `foo` and `-1`, and `foo-_1` is `foo` and `_1`.** It split only at a dash a digit follows, so these kept the whole string as the name and an empty version. Upstream's `DrvName` (names.cc, the same at 2.24.9, 2.35.4 and 2.36.0) splits at the first dash whose next character `isalpha` rejects, and upstream 2.36.0 sets no locale, so only `A` to `Z` and `a` to `z` are letters and a dash before a byte outside ASCII splits too. A dash that ends the string splits nothing, so `foo-` stays whole. A profile already named an element by this rule, through a second copy of the split; both now use the same one.
- **Library API:** `Nix.DrvName` (new) holds the split, `drvNameDash`, which takes the `uncons` of the string it reads, so it counts bytes for `builtins.parseDrvName` and characters for `Nix.Profile.Manifest.drvNameName`.
