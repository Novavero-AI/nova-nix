- **On Linux and macOS a build's `PATH`, unless its derivation sets one, is upstream's `/path-not-set`, so a builder finds no program its derivation does not name, where nova-nix gave it the builder's own directory, that directory's sibling `usr/bin`, `/usr/bin`, `/bin` and `/usr/local/bin`.** Upstream's `initEnv` (unix-derivation-builder.cc at 2.36.0, the same in 2.24.9 and 2.34.9) sets `PATH` to `/path-not-set` before the derivation's own variables, a value naming no directory, so that a shell does not fall back to a search path of its own as it would were `PATH` unset; a derivation reaches a program on the host only by naming it, and nova-nix's builds reached the host's tools unasked, so a derivation that built here could fail upstream. Windows keeps the builder's directory, its sibling `usr\bin` and the system's directories, which `cmd.exe` and a job's environment need; upstream's Windows builder passes on the `PATH` it was started with.
