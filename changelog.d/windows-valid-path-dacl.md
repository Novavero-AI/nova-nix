- **On Windows registering a store path gives each of its files and directories the store's account as owner and a protected access control list no build account can change, and where the machine has a local `nixbld` group, the store directory lets that group create entries in it and nothing else.** Builds are to run as build accounts in a local `nixbld` group, as upstream's Linux builds run as `nixbld` users, and a path a build made would otherwise keep the permissions its build gave it, so the account that built it could change or delete it once it was valid. Registration now sets, on every node of the path, a link included and not followed, the account nova-nix runs as as the owner, as upstream gives each node of a path to the store's user, and a protected DACL that grants that account, SYSTEM and Administrators full control, Users and the `nixbld` group read and execute, and the node's owner read-control alone (OWNER RIGHTS), which takes the place of the rights an owner otherwise keeps whatever the DACL says. An access control list is no part of a NAR, so a path's hash is unchanged. Where the machine has a local `nixbld` group, a store directory nova-nix creates grants its entries to itself alone and the group FILE_ADD_FILE, FILE_ADD_SUBDIRECTORY, traverse, read attributes and synchronize, so what a build makes there takes its own token's default DACL rather than one passed down; the check of a store's directories accepts that grant on the store directory alone, and only applying to the directory itself. A machine with no `nixbld` group keeps a single-user store as it was: its store directory passes its entries down as before, and a registered path grants what it would have inherited, with the user as its owner.
- **Library API:** `Nix.Store.Access` gains `StoreAccounts`, the account that keeps the store and the build accounts' group where there is one, which `accessSddl`, `securityDistrust` and `descriptorDistrust` now take in place of a `Sid`, the last two with the `DirAccess` of the directory checked; `StateAccess`, the state directory's access, which `StoreAccess` no longer stands for; `validPathSddl`, a registered path's security descriptor for a node of a `ValidNode` kind, a directory's entries passed down and a file's or a link's with no inheritance flags, which Windows keeps on no such node; and `withValidPathAccess`, the step `Nix.Store.canonicalizeMetadata` takes for each node. `AllowEntry` carries the entry's flags.
