- **Every reader of an attribute name a program computes refuses a name with string context, as upstream's does: `listToAttrs`, a dynamic attribute, a select or `?` path, `getAttr`, `hasAttr`, `removeAttrs`, `catAttrs` and `groupBy`.** Each read the name's text and dropped its context, so `builtins.getAttr (builtins.appendContext "a" { ... }) { a = 1; }` was `1`, and a `derivation` whose `outputs` held such a name passed where upstream's fails, since the wrapper makes its output attributes with `listToAttrs`. Upstream reads each name with `forceStringNoCtx` (`getName` and `ExprAttrs::eval` in eval.cc, and `prim_getAttr`, `prim_hasAttr`, `prim_removeAttrs`, `prim_listToAttrs`, `prim_catAttrs` and `prim_groupBy` in primops.cc), which refuses one with context as `the string 'a' is not allowed to refer to a store path (such as '...')`, naming the context's first element, and now so does nova-nix, with `builtins.unsafeGetAttrPos`'s reader. A name that is not a string is refused with that function's `expected a string but found ...` where each reader had a message of its own; a dynamic attribute whose name is null still binds nothing.
