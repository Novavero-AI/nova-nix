- **`nova-nix eval`, `build` and `trust` take a directory, a `<NAME>` the search path finds, and `--arg` and `--argstr`, and call a function the target evaluates to, as `nix-instantiate --eval` and `nix-build` do.** They took a file or `--expr` alone, and kept a function as the value it is. A directory stands for its `default.nix` (`resolveExprPath`, eval.cc:2968-2985 at 2.24.9). An argument longer than two characters and written in angle brackets is found and read as `import <NAME>` finds and reads its file (`lookupFileArg`, common-eval-args.cc:188-191): a name the search path does not hold fails with the same message, and a file found in the store keeps its store path, so a path literal in it names a place in that store path and the target gives the derivation `import <NAME>` gives. `--arg NAME EXPR` passes an expression, parsed with its relative paths against the working directory before the target is read and evaluated only when the function uses it, and `--argstr NAME STRING` a string; a later flag for a name replaces an earlier one (common-eval-args.cc:57-71 and 146-168). The expression, the string and a `<NAME>` are the bytes the command line gives, as upstream reads them; a name is an attribute name, which is text here, so one whose bytes have no UTF-8 reading is refused. A function with a set pattern is called as upstream's `autoCallFunction` calls it (eval.cc:1767-1814): one that takes `...` with every argument, any other with the arguments its formals name, its defaults filling the rest, and a set with `__functor` as the function its functor gives. A formal with neither an argument nor a default fails with upstream's `cannot evaluate a function that has an argument without a value` message, which upstream follows with the formal's position and nova-nix, whose formals carry none, does not. `eval` calls the value only when an argument is given, as `nix-instantiate --eval` does (nix-instantiate.cc:47-52). `eval --aterm` takes any of these targets, where it took only `--expr`, and calls the value whether or not an argument is given, as `nix-instantiate` does before it writes a derivation (get-drvs.cc:360). `build` and `trust` call it before each component of the `-A` path is selected from it and once the path has selected it, as `nix-build` does through `findAlongAttrPath` and `getDerivations` (attr-path.cc:56-60, get-drvs.cc:360), so `build '<nixpkgs>' -A hello` calls nixpkgs' function before it selects `hello`. A URL or `channel:` target, which upstream downloads, `--arg-from-file` and `--arg-from-stdin` are not accepted, and a command given no target still asks for one, where upstream reads `default.nix` in the working directory.
- **`nova-nix eval`, `build` and `trust` read `--expr` as the bytes the command line gives, as upstream does.** The expression was decoded as text first, so a byte with no reading in the file-system encoding, such as a Latin-1 byte in a string literal, became U+FFFD and could change a derivation without a word. On Windows, where the command line is UTF-16, an expression holding an unpaired surrogate, which has no UTF-8 form, is refused.
- **Library API:** `Nix.Eval.AttrPath.selectAttrPath` takes, first, the action the value each component selects from is passed through, `pure` for none. `Nix.Eval.AutoCall` is new, with `autoCallFunction` and `AutoArgs`; `Nix.Eval` exports `findInSearchPath`, the lookup `builtins.findFile` makes; `Nix.Eval.IO` exports `resolveImportTarget` and `readImportTarget`, which find and read a file as `import` does; and `Nix.Environment` exports `argumentBytes`.
