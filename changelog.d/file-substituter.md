- **A `file://` URL in `substituters` or `--substituter` names a binary cache in a directory, and a build substitutes from it as upstream substitutes from its local binary cache store, so a cache `push` writes to a drive can be carried to another machine and read there with no web server (`file:///D:/cache` on Windows).** The substituter read only HTTP: it handed every URL to its HTTP client, so a `file://` one failed every query. A directory cache's narinfos and NARs now go through the steps an HTTP cache's do: a narinfo must name the path and carry a signature a key in `trusted-public-keys` verifies, the NAR is decompressed by the narinfo's `Compression` and held to its `NarHash`, `NarSize` and content address, and caches are asked in priority order. A narinfo the directory lacks is a miss and a NAR it lacks is a substitute gone, as a 404 is for an HTTP cache; a file that cannot be read fails, and is not retried, since upstream retries downloads alone. A narinfo `URL` that is empty, absolute or holds a `.` or `..` segment is refused in upstream's words (`local binary cache path '../x.nar' must not contain '..' or '.' segments`), so a narinfo cannot name a file outside the cache. The first query of a run opens each `file://` cache as upstream's store opens one: it makes the `nar`, `build-trace-v2` and `log` directories, writes a `nix-cache-info` holding `StoreDir: /nix/store` where there is none, and reads the one there. A cache whose `StoreDir` is another store directory is passed over for the run after upstream's warning, `binary cache 'file:///D:/cache' is for Nix stores with prefix '/gnu/store', not '/nix/store'`, as upstream drops a substituter it cannot open, and so is one whose URL `push` would refuse or whose directory cannot be made or read. The cache is asked at the `Priority` its `nix-cache-info` states, or at upstream's default of 0 when it states none, as a `push` writes it, so such a cache comes before the HTTP caches, which nova-nix asks at 50. A `Priority` that is not a 32-bit integer fails the query whatever `fallback` says, as it fails upstream's command, in nova-nix's words, since upstream's are the C++ library's. `WantMassQuery` is not read: it governs only queries about many paths at once, which nova-nix does not make. The URL is read as `push` reads one: an empty host and an absolute path, with no query, fragment or percent-escape, where upstream would read a query such as `?priority=10` as the store's settings. An HTTP cache's `nix-cache-info` is still not read, so its priority is the configured one and its `StoreDir` is not checked: with `substituters = https://cache.nixos.org file:///D:/cache` and `Priority: 45` in the directory's `nix-cache-info`, nova-nix asks the directory first, where upstream asks cache.nixos.org, whose file states 40. A substitution makes only the directories the newest upstream release makes, so it opens a cache that release wrote, which lacks `realisations`, from a drive it cannot write to; a push makes `realisations` as well, for a reader of an older release. Each `file://` cache is opened once a run, where upstream opens it once a process, so `trust`, which makes a run for each fixed-output input, warns of a cache it passes over once for each.
- **`push` names a cache on Windows as upstream does, `file:///D:/cache`, in its refusal of a `nix-cache-info` for another store directory, names the cache when its directory cannot be made or read, and refuses a `nix-cache-info` whose `Priority` is not a 32-bit integer.** The refusal joined `file://` to the directory, which gave `file://D:/cache`. A push opens the directory as a substitution does, and upstream's `nix copy --to file://` fails on such a `Priority` as its substitution does.
- **Library API:** `Nix.CacheDirectory` holds what is shared by a push to a directory and a substitution from one: `cacheInfoFileName` and `cacheInfoText`, which `Nix.Push.Directory` exported, and `readCacheInfo`, which replaces its `checkCacheInfo` and returns a `CacheInfo` or a `CacheOpenFailure`. In `Nix.Substituter`, `NarInfoMemo` and `emptyNarInfoMemo` are `CacheMemo` and `emptyCacheMemo`, `sortCaches` is not exported, and `readBodyCapped` and `cappedBodySource` take an `IO ByteString` chunk source, the type http-client's `BodyReader` already was.
