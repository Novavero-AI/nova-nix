- **The command-line reference, which `--help` prints, says what `eval`, `trust`, `store gc`, `develop` and `profile remove` do, where it said otherwise.** `eval` writes `builtins.toFile` and `builtins.path` to the store only under `--read-write-mode`; without it, it builds an output a path's context names only when its derivation's `allowSubstitutes` is false and `always-allow-substitutes` is off, refusing to substitute any other. `trust` in a store upstream Nix's database also manages refuses a closure only when it has a fixed-output input. `store gc --print-roots` lists the roots in such a store too. `--ignore-env` keeps the variables `--set-env-var` sets as well as those `--keep-env-var` names. `profile remove --regex` matches a package's identifier: for one a flake added, its flake reference and attribute, and for any other the names of the store paths it holds, without their versions.
