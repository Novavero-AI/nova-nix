- **A binding, list element, call argument or default whose value is a variable holds that variable's own value wherever upstream's does, so `builtins.catAttrs "g" [ { g = map; } ] == [ map ]` is `true`, where it was `false`.** Upstream's `ExprVar::maybeThunk` binds a variable's own value when the slot it reads is filled and a thunk of its own when it is not, and makes a thunk for a variable only a `with` supplies (eval.cc:863-872 and :1014-1021 at 2.24.9), and `==` takes a value as equal to itself before it compares (eval.cc:2727), which a function, never equal to another, shows. nova-nix shared a variable only when it read it by slot, and made each value a recursive set, a `let` or a default gives a name, but an inherited one, a thunk of its own, its frame not being built yet; it now shares a global, a variable of an enclosing scope and a name of a recursive set with a dynamic name as upstream does. A recursive set, a `let` and a set pattern fill their slots in symbol order, from an env whose slots start empty (eval.cc:1211-1221, :1295-1300 and :1539-1563; eval-inline.hh:78), so a variable naming a sibling shares its value only when the sibling's name was interned first: `let s = rec { f = x: x; g = f; }; in builtins.catAttrs "f" [ s ] == builtins.catAttrs "g" [ s ]` is now `true`, as it is with `${"g" + ""} = f`, and with `rec { g = f; f = x: x; }` it stays `false`. A recursive set's dynamic names are bound once its static ones are (eval.cc:1273). A default naming a formal shares whatever that formal's slot holds, the argument's attribute when the call gives one, and a default naming the @-pattern shares the argument. A recursive set that binds `__overrides` makes every value but an inherited one a thunk of its own (eval.cc:1214-1218), and does so here too, though nova-nix does not yet apply `__overrides` (#601). A constant in a recursive set, a `let` or a default is now a value rather than a thunk, as upstream's is. The compiler decides which bindings share as it compiles a frame, so a frame that has none pays one read of their count; on `profiling/stress.nix` evaluation allocates 1,134,852,296 bytes where it allocated 1,135,482,952, and a `let` binding a variable of an enclosing scope allocates 6% less over 200,000 evaluations.
