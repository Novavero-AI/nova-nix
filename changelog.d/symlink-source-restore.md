- **A derivation whose source is a symlink builds, and a copy is restored from the tree evaluation hashed.** A coerced path that is a link is copied as the link, as 2.34.9 and newer copy it, and the build driver restores it as the link; `src = ./link`, with `link` pointing at a directory or a file, had failed with `refusing to register /nix/store/...-link: .../link changed after evaluation hashed it`, since evaluation hashed what the link pointed to and the restore dumped the link. Evaluation still follows the links among a path's ancestors, so the restore now reads the path evaluation read, those links resolved, rather than the path as written: a coerced path below an absolute link inside a store path, as a NAR carries one into another store path, is restored from the store nova-nix was given rather than through the link on the host, and the tree is read under the case-hack its resolved text calls for, as evaluation read it. A copy `builtins.path` or `builtins.filterSource` makes, of what a link points to, is written by evaluation itself and never restored this way.
- **Library API:** `Nix.Store.Ops.EvalObjects`' `eoSources` is a `Map StorePath Text`, each copy's store path with the path-value text of the tree it is restored from, and `Nix.Store.materializeEvalSources` takes that map. `Nix.Eval.IO.EvalState`'s `esSourcePathCache` holds a `SourceCopy` per coerced path, and `sourceCopies` gives the map from it.
