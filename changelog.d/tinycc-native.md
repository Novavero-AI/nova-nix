- **`pkgs/windows` builds TinyCC as a native Windows compiler: `tinycc-native.prev`, TinyCC's own source compiled by `tinycc-mes` with `_WIN32` defined, against TinyCC's `win32/` headers, and `tinycc-native`, the same source compiled by that, each linked against msvcrt.dll and kernel32.dll through the import tables tcc writes from TinyCC's `.def` files.** It is compiled with upstream's `win32/build-tcc.bat` defines, `-DTCC_TARGET_PE -DTCC_TARGET_I386`, as one executable, and each round compiles the thirteen objects `build-tcc.bat` archives as `libtcc1.a` and copies its five import libraries for the next; nothing it builds links Mes. `build-tcc.bat`'s `runmain.o`, `bcheck.o` and `bt-*.o` are not built, so `-run`, `-b` and `-bt` are not available. Where upstream's `tcc.exe` finds `include` and `lib` beside itself, `tinycc-native` reads its headers from `C_INCLUDE_PATH` and its runtime from `-B`, as the rounds before it do, since a store path, spelled with a backslash, cannot be a C string. It predefines `__MINGW32__`, as MinGW's GCC does and TinyCC does nowhere, through `CONFIG_TCC_SWITCHES`, which upstream's `configure --tcc-switches` sets, since Windows sources such as busybox-w32 choose their Windows code by it. A tcc compiled with `_WIN32` adds the Windows system directory to its library paths, so the import libraries it links by default, msvcrt's and kernel32's among them, are read from the DLLs there when the directory a script names lacks their `.def` files; a fifth edit to the TinyCC source removes that call, and such a link fails. nixpkgs' `static_link` edit stays, so an explicit `-lkernel32` does not find `kernel32.def`, and a script names another import library by its path or as `-l:name.def`. It is built without `-g`, as `build-tcc.bat` builds it, since the debug information names the build directory. CI builds both on x64 and ARM64, checks that `tinycc-native`'s `tcc.exe` is the same bytes as the one `tinycc-mes` compiled, that it searches the `-B` directory alone and predefines `__MINGW32__`, and runs a hello, the double's two words and a double printed through `printf`'s `%f`, each linked against msvcrt and ending its lines in a carriage return, as msvcrt's text-mode stdout writes them.
