- **A type error shows an attribute that is still being forced as the potential infinite recursion marker, as upstream's does, where it showed the thunk marker.** Upstream renders the value a type error names as it builds the error: `forceList` hands the value to the message (eval-inline.hh), and `HintFmt` formats each argument as it is given (fmt.hh), while the attribute is still being forced, and the printer shows such an attribute as that marker (`Printer::printThunk` in print.cc). So `let x = { a = builtins.length x; }; in x.a` fails with `expected a list but found a set`, its `a` printed as the marker, under both. nova-nix rendered the message when it was shown, by which time the failed force had put the attribute back to unevaluated.
