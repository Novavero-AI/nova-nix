- **`nova-nix eval` computes the store paths of `builtins.toFile`, `builtins.path` and `builtins.filterSource` without writing them, as `nix-instantiate --eval` does, and `--read-write-mode` writes them as `eval` did before.** `eval` wrote each such object into the store, making the store if there was none, so evaluating `builtins.path { path = ./f; }` changed the store and, in a store upstream Nix also manages, failed where upstream prints the path. `nix-instantiate --eval` runs read-only (`main_nix_instantiate` in nix-instantiate.cc): it copies with `FetchMode::DryRun` (`addPath` in primops.cc) and names a `toFile` result without adding the text (`prim_toFile`), and `eval` now gives the same paths and writes none of them. `trust` evaluates the same way, so in a store upstream Nix manages it no longer fails on a `toFile` or `builtins.path` the evaluation makes. What a fetcher fetches is still written, and now registered as it lands, making the store's database if there is none, since upstream's fetchers add their results in any mode (`fetch` in fetchTree.cc, `downloadFile` in tarball.cc and `Input::fetchToStore` in fetchers.cc at 2.24.9); a fetch pinned by a `sha256` whose path the store already holds returns that path without downloading or writing, as upstream's does (`fetch` in fetchTree.cc at 2.24.9, and at 2.34.9, whose ensurePath returns at once for a valid path), so a second evaluation of the same pinned fetch does not download it again. `--read-write-mode` evaluates as `build` does: it writes what evaluation makes, adds it and every derivation it recorded to the store once evaluation succeeds, so a later evaluation finds them valid, and adds nothing, and so is refused nothing in a store upstream Nix manages, when evaluation made nothing, and builds or substitutes what an import from derivation names, through `--substituter`, `--trusted-key`, `--fallback` and `--exec-wrapper`, which `eval` now takes. `nova-nix build` writes as before.
- **Library API:** `Nix.Eval.Types.MonadEval` has a new method with no default, `pinnedFetchHeld :: StorePath -> m Bool`, which `PureEval` answers `False`, and a read-only `SessionStore`, `ReadOnlySession` over a `StoreQueries` and a `StoreOps`, writes and adds only what a fetcher fetches. `Nix.Store.Ops`'s local `soAddEvalObjects` adds nothing, and refuses nothing, for an evaluation that made nothing. `Nix.Eval.RealiseContext` exports `readableIn`.
