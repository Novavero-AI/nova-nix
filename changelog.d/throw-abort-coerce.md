- **`throw` and `abort` coerce their message as string interpolation does, as upstream's do: `throw { __toString = self: "m"; }` throws `m`, a throw `builtins.tryEval` still catches, and `throw 1` fails with `cannot coerce an integer to a string: 1`.** nova-nix took only a string, and refused anything else with `builtins.throw: expected a string` or `builtins.abort: expected a string`. Upstream's `throw` and `abort` (primops.cc, the same at 2.24.9, 2.34.9 and 2.36.0) read their message with `coerceToString` at its defaults, so a set with `__toString` or `outPath` is a message, and a path is one as the store path it is copied to.
