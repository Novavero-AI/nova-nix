- **`nova-nix trust --json` prints the report as one JSON document, and the report names a file of prebuilt code that is a copy of an input the closure runs as a builder as that input.** The lines are for a reader; the JSON is for a check, which can then hold a closure to what it relies on without reading prose. It has a `version`, the fixed-output inputs keyed by output path, each with its `class`, how it comes to be, the inputs pinned to the same hash, the builders inside it, and the prebuilt code and unread files its scan found, then the builders outside the closure, in its input sources and the builtins, each with its count of derivations, and the input sources themselves. Keys are camelCase and store paths full, as upstream's JSON output spells its own, and `--pretty` and `--no-pretty` lay it out as they do `print-dev-env --json`. Every file of prebuilt code now carries its SHA-256, and one whose bytes are those of a fixed-output input a build runs as a builder, hashed flat, is named as that input: `pkgs/windows`' stage0-pe32 source archive holds a copy of the 1,623-byte seed, which the report now gives as the seed rather than as more prebuilt code.
- **Library API:** `Nix.Trust.FoundCode` has a third field, `fcSha256`, the file's SHA-256 in lowercase base-16, and `TrustReport` a field `trBuilderBytes`; `trustReportJson` and `trustReportJsonVersion` are new, as is `Nix.Hash.sha256LazyHex`. `Nix.Cli.Args.CmdTrust` takes a `TrustFormat` and a `JsonLayout`.
