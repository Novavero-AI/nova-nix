- **`nova-nix develop` starts `bash` with the build environment of a derivation, and `nova-nix print-dev-env` prints that environment, as upstream's `nix develop` and `nix print-dev-env` do, on Linux and macOS.** Both take `build`'s targets and its evaluation, store and sandbox flags. A derivation whose builder is not `bash` is refused in upstream's words. The environment is captured as upstream captures it: a copy of the derivation named `NAME-env`, whose builder runs upstream's 2.35.4 `get-env.sh` to write what bash holds once the stdenv's setup has run, so that the copy's path is upstream's at 2.34.9 and 2.35.4. The copy is built or downloaded with what it depends on, as `build` builds, and a second run builds nothing. The shell runs upstream's rcfile: `--command` runs a command with every argument after it, `--phase` and the phase flags (`--unpack` through `--installcheck`, `--check` among them) run a phase through `runPhase`, and the `bash-prompt`, `bash-prompt-prefix` and `bash-prompt-suffix` settings set an interactive shell's prompt. `--ignore-env`, `--keep-env-var`, `--unset-env-var` and `--set-env-var`, with 2.24.9's spellings as aliases, shape the shell's environment, which also gets `NIX_GCROOT` and `SHELL`; their conflicts are upstream's usage errors, and those upstream finds only once the environment is built are found then here too. nova-nix replaces itself with the shell, as upstream does, so that the shell has the terminal and its signals to itself and the command exits with its status, and no descriptor nova-nix holds, such as a connection a substitution left open, reaches the shell. The shell is `bash` found on the `PATH` of the environment it starts with, which is what upstream starts with flakes off, where `nixpkgs#bashInteractive` cannot resolve. `print-dev-env --json` prints the environment as upstream's does, over several lines when stdout is a terminal and on one otherwise, or as `--pretty` and `--no-pretty` choose. Upstream's `develop` leaves an empty temporary directory behind on every run, and an empty rcfile when it refuses its flags; nova-nix leaves neither. On Windows both commands are refused, since no Windows stdenv's builder is bash yet. The garbage collector does not yet keep the environment while a shell runs.
- **Library API:** `Nix.Develop.Shell` holds what a `develop` shell runs (`shellModeFor`, `shellArguments`, `bashProgram`) and the environment it starts with (`shellEnvironment` over `EnvironmentChanges`), refusing what upstream refuses in its words, and `developHost`, the host's temporary files, environment and exec, which is `Left` on Windows. `Nix.Eval` exports `inputModuloHashes`, `Nix.Develop.Environment` exports `appendPath`, and `NixConfig` gains `ncBashPrompt`, `ncBashPromptPrefix` and `ncBashPromptSuffix`, which a record built without `defaultNixConfig` needs.
