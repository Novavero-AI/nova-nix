- **`push --cache file:///DIR --secret-key-file KEY` writes a binary cache to a directory, as upstream's `nix copy --to file:///DIR` does, so builds can be shared from any static web server or file share.** `push` reached only a nova-cache server, which signs what it receives. The directory gets the layout upstream's `LocalBinaryCacheStore` writes at 2.24.9: `nix-cache-info` holding `StoreDir: /nix/store` (`BinaryCacheStore::init` in binary-cache-store.cc), without which upstream's HTTP substituter reads no cache, a `<hash>.narinfo` for each path, and its NAR under `nar/`, named by the hash of the file (`BinaryCacheStore::addToStoreCommon` in binary-cache-store.cc). It also gets the empty `realisations`, `build-trace-v2` and `log` directories. Upstream's `file://` store creates `nar`, its realisations directory and `log` whenever it opens a cache, to read it as well (`LocalBinaryCacheStore::init` in local-binary-cache-store.cc), and a reader that cannot create them, without write access to the directory, drops the cache with only a warning (`getDefaultSubstituters` in store-api.cc at 2.24.9, store-registration.cc at 2.36.0). The realisations directory is `realisations` through Nix 2.34.9 and `build-trace-v2` from 2.35.4, so both are made. Each narinfo is signed with the secret key, a file in the form `nix-store --generate-binary-cache-key` writes, as upstream's binary cache store signs every narinfo with the key its `secret-key` setting names (`BinaryCacheStore::addToStoreCommon` in binary-cache-store.cc at 2.24.9, `BinaryCacheStore::uploadNarInfo` at 2.36.0). A key file whose second half is not the public key of its seed is refused, since upstream's signer, libsodium's, signs with that half as the public key, and what it signs with such a key verifies under no key. A path whose narinfo is in the directory is skipped and a NAR whose file is there is not written again, as upstream skips them; every NAR is written before any narinfo; each file is written beside its name and renamed onto it, with the permissions the umask leaves, so a web server running as another user can read it; and a `nix-cache-info` naming another store directory is refused in upstream's words. The NARs are uncompressed unless `--compression zstd` is given, where upstream's default is xz: nova-cache decodes xz but has no encoder. A `file://` cache needs `--secret-key-file`, since nova-nix's substituter refuses a narinfo with no signature, and so does upstream's unless `require-sigs` is off or the cache is marked trusted; it refuses `--key-file`, a server's API key, and a server refuses `--secret-key-file`. A `file://` URL names an absolute path after an empty host, as upstream requires, and not a filesystem root such as `file:///`, which a variable that expanded to nothing leaves; one with a query, a fragment or a percent-escape is refused, since upstream reads the query as store settings and decodes escapes, and on Windows `file:///C:/DIR` names `C:/DIR`. A `--cache` that is no `http://`, `https://` or `file://` URL is refused before the store is opened, where it failed at the first request.
- **Library API:** `Nix.Push.Directory` is new: `pushToDirectory` writes a closure to a directory cache as `DirectoryPush` describes it, `loadSecretKeyFile` reads a signing key, and `pushTarget` tells a server's URL from a directory's. `Nix.Push.loadApiKeyFile` is renamed `loadKeyFile`, since it reads either kind of key, and `narInfoFileName` and `narDirSegment` are exported.
