- **An evaluation builds its base environment once, and evaluates every file it imports in it, as upstream's does, where each imported file built the root environment and the `builtins` set again; and every C value the evaluation keeps from one step to the next is registered as a root.** Upstream's `EvalState` builds one base environment as it is constructed (`createBaseEnv`, primops.cc at 2.24.9), with the `derivation` wrapper in it, and keeps its import cache where its collector scans it (`fileEvalCache`, eval.hh:328-332). An evaluation session now builds its base environment as it starts, over the policy and the search path it is given, with the session's own `derivation` wrapper, where the wrapper was one value for the process. The empty list's cell is a C static, like `null`'s. So no constant of the program points into the C data layer's arena, and tearing the arena down and setting it up again starts evaluation afresh. The base environment, with the search path in `builtins.nixPath`, and each value the import cache keeps are registered as roots (`Nix.Eval.CRoots`), which the census `nova-nix eval` writes under `NOVA_NIX_C_STATS` marks from. What any program evaluates to is unchanged.
- **Library API:** `Nix.Eval.IO.EvalState` no longer exports its constructor or `esPolicy`, `esTimestamp`, `esSearchPaths` and `esImportCache`, which the session fixes as it starts, and `evalBaseEnv` gives the environment to evaluate a file in. `Nix.Builtins.builtinEnvWithScope` takes the base environment to overlay. `Nix.Eval.CRoots` (new) registers roots, `Nix.Eval.CStats.CRoot` has `RootRegistered`, and `Nix.Eval.CThunk` exports `cthunkEmptyList`.
