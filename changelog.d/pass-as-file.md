- **An attribute named in `passAsFile` reaches the builder as a file in the build directory, named by `<name>Path`, rather than as a variable, as upstream passes it.** The builder put every attribute in the environment, so a builder that reads only the file failed: the minimal bootstrap's `writeTextFile` in nixpkgs runs `cp ${textPath} ${target}` with no fallback. Builders that fall back to the variable, as stdenv's `genericBuild` and `writeTextFile` do, got the value through the environment, under the size limit `passAsFile` exists to avoid, and one holding bytes that are not UTF-8 failed the build although it never needed to be text. Upstream (`initTmpDir`, local-derivation-goal.cc at 2.24.9) splits `passAsFile` at spaces, tabs, newlines and carriage returns, writes each attribute it names to `.attr-` followed by the Nix base-32 SHA-256 of the attribute's name, sets `<name>Path` to that file and leaves the attribute itself out of the environment. A name with no attribute is ignored, an attribute literally called `<name>Path` keeps its own value, and a structured-attributes derivation ignores `passAsFile`. nova-nix now does each of these, and its file name for `foo` is the one upstream's own test pins. The file holds the bytes the variable would have held, store paths and placeholders rewritten and every other byte as the derivation has it, and an output passed this way holds the path the build writes it to. On Windows the variable joins the build directory and the file name with a backslash, as `NIX_BUILD_TOP` is spelled, where upstream writes `/`.
- **Library API:** `Nix.Builder` exports `AttrsDelivery` and `attrsDelivery`.
