- **On Windows a path with a root but no drive, such as `/probe/f.txt`, names that path on the store's drive, whatever drive is current.** It resolved against the current drive, so with `C:\probe\f.txt` in place `builtins.pathExists "/probe/f.txt"` was `true` from `C:\` and `false` from `D:\`, and one value named different files depending on where the evaluator ran. The drive is now fixed by configuration: `C:` for the default `C:\nix\store`, or the drive of the directory `--store` names. The value keeps its spelling, so `toString /probe/f.txt` is still `"/probe/f.txt"`, and a `/nix/store` path resolves through the store directory as before, not through the store drive's `\nix\store`. The rule holds at every place a path reaches the filesystem: `readFile`, `pathExists`, `readDir`, `readFileType`, `hashFile`, `import`, `scopedImport`, search path lookups, copies into the store, and the local paths `fetchurl`, `fetchTarball` and `fetchGit` hand to curl and git, which receive the drive as `file://C:/...` or `C:/...`. Under `--restrict-eval` and `--pure-eval` the check uses the same drive as the read, so a search path root given without a drive admits the drive-qualified spelling of the same files, and the reverse. A path that names a drive, and every path on macOS and Linux, behaves as before. Upstream resolves such a path against the current drive too, and NixOS/nix issue 16412 has that design open.
- **Library API:** `Nix.Store.Path.qualifyPathText` names path-value text on the store's drive, and `storeTextToFilePath` applies it to every path outside the store. `Nix.Eval.Policy.uriAccess` takes the `StoreDir` first, and `fileUrlPrefix` is exported. `MonadEval` gains `qualifyPath`, and `Nix.Eval` exports `localFileUrl` and `gitRemote`.
