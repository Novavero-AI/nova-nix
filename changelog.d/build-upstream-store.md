- **`build` refuses a store directory that upstream Nix's database also manages, such as `/nix/store` where upstream Nix is installed, and names that database; `eval` refuses one at the evaluation's first write to it.** A path upstream registered has no row in nova-nix's database, so a build that came to build or substitute such a path took upstream's tree for a leftover of its own: it removed the tree before the builder ran, again when the build failed, and before unpacking a substitute, leaving upstream's database recording a NAR hash the new tree need not have, or a path that no longer existed. The build is refused before anything is evaluated, for the same stores `store gc` and `store delete` refuse, so a store of nova-nix's own beside upstream's, such as `/nix/nova-store`, builds as before. An evaluation's own store writes (`builtins.toFile`, `builtins.path`, the fetchers) clear a tree that does not reproduce its address, which in such a store may be one upstream registered or is writing, so an evaluation stops with an error at its first write there; one that writes nothing, such as computing a derivation's path, is not refused. Evaluating a nixpkgs package's store path writes to the store, so it needs a store of nova-nix's own, given with `--store`. `push` and `store gc --print-roots`, which change no path in the store, are not refused.
- **Library API:** `Nix.Store.Upstream` also holds `upstreamManagedRefusal`, which gives the reason an operation is refused for a store directory upstream Nix's database may also manage, worded for what the operation would do to upstream's paths (`UpstreamHazard`). For such a store, before they write anything, `Nix.Builder.buildDerivation` and `buildWithDeps` return `BuildFailure`, and `checkDerivation` returns `Left`. `Nix.Substituter.unpackAndVerify` and `fetchSubstituteWith` return `SubstError`, so `Nix.Builder.substitutePaths` returns `NotFetched`, each path `DeliveryFailed`. `Nix.Store.materializeEvalSources` throws an `IOException`, and the `Nix.Eval.IO` evaluator's store writes (`writeToStore`, `copyPathToStore`, `addSourceNar`, `addFixedOutputFile`) fail the evaluation with an error `builtins.tryEval` does not catch.
