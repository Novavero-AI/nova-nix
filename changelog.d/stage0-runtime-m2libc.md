- **`pkgs/windows`' stage0-pe32 links every compiled program against M2libc's Windows runtime, and M2libc's `fseek` returns 0 on success.** The startup, system calls, C library glue and PE-end shim a compiled program links against now live in M2libc's `x86/windows/`, beside its C, as M2libc carries its Linux runtime, so a merge of upstream M2libc shows where the two runtimes need the same change. stage0-pe32 keeps its own copies of the PE header and the ntdll plumbing for the hand-written M0 and cc_x86, as stage0-posix keeps its own ELF header, and one generator writes both. The moved files are byte for byte the ones stage0-pe32 held, and comments that contradicted the code are corrected in both repositories. M2libc's `main` also carries the two fixes it offers upstream: `fseek` returned the new position where ISO C 7.21.9.2 requires 0, and armv7l's `close`, `unlink` and `chroot` passed the kernel their argument's address. No program in the chain reads `fseek`'s result, but hex2-new and kaem link the `stdio.c` that holds it, so their bytes change; every other link is unchanged.
